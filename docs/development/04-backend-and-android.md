# 后端、管理界面与 Windows / Android 客户端集成规范

## 1. FastAPI 分层

职责边界：

- `application.py`：创建 FastAPI、注册中间件与 Router。
- `api/`：按领域组织 Router，只做输入校验、调用与响应映射。
- Service / use case：下载、翻译、任务编排等业务规则。
- Repository / `db.py`：SQLite 查询、事务和记录转换。
- Site Plugin / `site_plugins/`：按站点声明匹配、能力和运行处理器。
- Adapter / `scraper.py`：共享 HTTP、OCR、文件格式与外部模型协议。

新增业务不得继续堆入单一入口。修改现有大型模块时，优先将正在变更的完整用例提取到对应层，并保持测试覆盖。

## 2. API 约定

- 业务 API 使用 `/api/v1` 前缀；`/healthz` 仅供进程与 systemd 存活检查。
- API 只暴露必要字段，使用 Pydantic 模型验证输入输出。
- 资源不存在返回 `404`，校验失败返回 `422`，业务冲突使用 `409`。
- 错误正文使用稳定的 `detail`，不得返回 Python 堆栈、密钥、Cookie 或本机完整隐私路径。
- 列表排序和分页规则必须确定；任务状态使用稳定枚举值。
- 长任务立即返回任务记录，通过轮询查询进度，不让单次请求无限等待。
- 客户端与服务端日期格式保持一致，并明确时区语义。
- 对外 DTO 不得包含 `localPath`、`filePath`、数据目录、内部文件名或服务器绝对路径。
- 认证后的 `/api/v1/meta` 返回服务标识、应用版本、API 版本、实例 ID 与运行能力，客户端保存连接前必须校验。

Linux 后端在反向代理或私有网络之后运行，业务 API 必须启用 Bearer Token；未配置认证时服务必须
拒绝监听非回环地址。公网访问必须使用
HTTPS，FastAPI 不直接承担公网 TLS 终止。

### 认证与凭据

- `/healthz` 不认证，只返回稳定的存活状态，不包含版本、路径或配置。
- Linux 远程服务的 `/api/v1/*` 默认全部认证；Token 从 `Authorization: Bearer` 读取并使用常量时间比较。
  Windows 本机服务只能监听回环地址，可不配置 Bearer Token。
- 服务端只保存高熵 Token 的 SHA-256 摘要；启动日志、异常与 OpenAPI 不得显示原始 Token。
- 客户端将 Token 保存到操作系统提供的平台安全存储，普通偏好只保存根地址。
- 设置读取不返回翻译密钥或账号密码明文，只返回是否已配置；更新使用“保留、替换、删除”语义。
- 认证图片与导出下载遵循相同规则。客户端只向配置后端的同源 URL 附加 Token，避免泄露给第三方封面或重定向目标。
- Linux 后端使用两层凭据：Bearer 连接 Token 保护实例入口，`X-QingJuan-User-Token` 标识当前用户。注册与登录仍须先通过连接 Token；
  书架、任务、阅读进度、文件资源、导出和异步导入任务全部按当前用户隔离。Windows 本机模式关闭多用户能力并隐式使用管理员主体。
- 书源目录、搜索、插件清单、脱敏设置和模型状态至少要求有效用户会话；书源导入/启停、插件启停等影响全服的写操作只允许管理员。
  Bika 邮箱、密码与登录 Token 视为管理员配置的服务级抓取凭据，与翻译模型密钥一样由整台后端共享，不代表或同步任一用户的青卷书架；
  多用户模式未配置凭据时必须返回可执行错误，普通搜索、预览或下载请求不得自动注册账号或写回全局设置。Windows 单用户模式可保留自动建号。

### 阅读定位与链接任务重试

- `PUT /api/v1/books/{book_id}/progress` 兼容原有章节、滚动比例和段落/图片锚点，另接受可空的 `pageIndex`、`pageCount`、`layoutKey`、`contentMode`、`characterOffset`。响应使用对应的 `last*` 字段；书库记录提供 `lastReadPageIndex` 和 `lastReadPageCount`。页索引和字符偏移从零开始，页数为正，分页标识最多 256 字符，原文/译文模式为 `original` / `translated`。
- SQLite 升级以可重复执行的新增可空列保留旧阅读数据。旧客户端保存时清空不再有效的新定位字段；章节被删除或缩减时同步清除失效页码和锚点。阅读进度继续严格按当前用户及其书籍授权。
- 链接任务 POST 支持最长 128 字符的 `Idempotency-Key`，允许字母、数字和 `._:-`，按用户与键隔离。相同键与参数返回原任务，只调度一次；相同键但不同参数返回 409。去重与当前链接任务一致，仅在后端进程生命周期内有效，不承诺跨进程重启恢复同一操作。
- 网站抓取必须校验所有解析地址并将连接固定到已验证的公网 IP；HTTP、curl 重定向和浏览器子资源均使用同一公网边界，不继承模型服务的内网白名单。失败信息保存在任务或章节状态，不能写作正文；正文经过成功校验后才原子替换旧文件，部分下载成功时据实际章节状态显示结果。

### 客户端设备登记与封禁

- Flutter 客户端首次启动时在普通偏好中生成 128 位随机设备 ID，后续安装生命周期内保持稳定；卸载或清除应用数据后可生成新 ID。
  设备 ID 不属于密钥，不得根据硬件序列号、账号、MAC 地址或广告标识推导。
- 携带 Bearer Token 的同源业务请求同时发送 `X-QingJuan-Device-ID`、百分号编码的
  `X-QingJuan-Device-Name` 和 `X-QingJuan-Device-Platform`。服务端严格限制字符集和长度，不信任客户端提供的显示名称。
- 服务端在 SQLite `devices` 表中保存设备 ID、显示名称、平台、首次与最后访问时间、直接网络对端地址和封禁状态；
  不保存设备 Bearer Token、完整 User-Agent、硬件标识或不受信的 `X-Forwarded-For`。
- 客户端前台运行时每 60 秒发送一次轻量心跳；最近 120 秒内有通过认证的请求或心跳视为“在线”。管理浏览器会话不计入设备数。
  旧客户端缺少设备头时继续兼容访问，但在升级并完成首次认证请求之前不能作为独立设备显示或封禁。
- 设备列表、在线数量、封禁与解封接口只接受管理界面的 HttpOnly 管理会话；写操作仍必须通过 CSRF 校验，普通 Bearer
  客户端不能枚举或修改设备记录。
- 已封禁设备携带相同设备 ID 的后续 Bearer 请求返回 `403`，不再访问业务 API；解封后可在下一次心跳恢复。
  设备 ID 是应用级稳定标识而不是硬件级不可伪造凭据。若共享连接 Token 泄露或对方能篡改客户端，应轮换连接 Token，
  不能把单设备封禁当作凭据撤销机制。

### Linux 管理界面认证

- 管理界面源码位于 `admin-web/`，构建结果位于 `python-backend/app/admin_static/`，由同一 FastAPI 进程在
  `/admin/` 提供；不得依赖 CDN、单独的 Node.js 进程或跨域 API。
- 管理密码与客户端连接 Token 分离。安装脚本生成高熵随机初始密码，只在首次生成它的 root 终端输出一次；
  服务环境只保存带随机盐的慢哈希，不保存或回传明文密码。
- 登录成功后使用短期、已签名、HttpOnly、SameSite=Strict 会话 Cookie。非只读业务请求还必须携带会话派生的
  CSRF Header；前端不得把密码、连接 Token 或会话 Cookie 写入 localStorage、sessionStorage、日志或 URL。
- 登录失败使用通用错误并限制连续尝试速率，不泄露配置状态。退出登录清除 Cookie；终端改密同时轮换会话签名密钥，
  使所有已有管理会话失效。
- Windows 客户端自己启动的回环后端显式设置 `QINGJUAN_DISABLE_ADMIN_WEB=1` 与 `QINGJUAN_TRUST_LOCAL_ADMIN=1`。
  前者阻止挂载管理 Router 和静态站点；后者仅在网络对端与 HTTP Host 都是回环地址时允许 Flutter 通过业务 API 保存模型设置和
  强制自检，且所有非只读请求必须携带客户端自动添加的 `X-QingJuan-Local-Request`，使跨站 HTML 表单无法借回环信任触发副作用。
  DNS 重绑定、非回环请求、普通源码启动和 Linux 部署不得获得该信任。Windows 启动器同时清空继承的远程认证与管理凭据环境。
- 管理界面与 Flutter 客户端访问同一业务 API 和数据库，不建立第二套业务规则。管理会话可查看全局服务资源，编辑用户显示资料、调整用户角色并管理账号状态；内置默认管理员不可降权或停用，
  角色变化后必须撤销该用户现有客户端会话；
  Flutter 的管理员用户会话仍只访问该管理员自己的书架。
- Linux 管理界面接受 `#settings` 与 `#plugins` 页面深链接：登录后分别选中“模型设置”和“插件管理”，其他未知 Hash
  回退“服务概览”。菜单内部切换同步 Hash，但不得把 API 密钥、密码、Token 或表单值写入 URL。
- 私有网络可使用 HTTP；任何公网访问仍必须由受信反向代理提供 HTTPS。页面和 API 必须同源，禁止将管理 Cookie
  或 CSRF 值发送到第三方地址。

### 管理端系统诊断

- `/admin/api/diagnostics` 只接受有效的 HttpOnly 管理会话并返回 `Cache-Control: no-store`；普通客户端 Bearer
  Token 不得读取诊断结果。接口为只读 GET，不提供执行命令、重启进程、清理文件或修改配置的能力。
- 应用工厂为每个 FastAPI 实例维护独立的进程内请求指标，包括总请求数、`4xx` / `5xx` 数量、平均耗时和最近
  500 次请求的 P95。静态资源和健康探针不计入指标；进程重启后指标重新开始，不把监控样本写入 SQLite。
- 诊断聚合服务运行时长、Python 与操作系统类型、数据库/运行日志占用、数据卷总量与剩余量、书库/任务/设备
  数量，以及数据库连通性、数据目录可写性、任务执行器、运行日志和磁盘余量检查。它只读取应用已经拥有的资源，
  不探测主机上的其他服务、用户、端口或日志。
- 最近异常从青卷自己的结构化轮转日志中选择有限条 `warning`、`error` 或 `critical` 记录，并在返回前再次脱敏。
  所有诊断 DTO 使用稳定字段，不返回 PID、主机名、环境变量、绝对路径、数据库内容、正文、Token、模型密钥、
  管理密码、Cookie、CSRF 或会话签名密钥。
- 前端下载的诊断报告只序列化上述安全 DTO，并附带报告格式版本和导出时间；不得重新请求密钥接口或把浏览器
  存储、完整运行日志、当前 URL 查询参数加入报告。

### 服务端翻译模型与连接自检

- 当前后端 SQLite 中的 `translationModel` 是唯一权威配置。Linux 只有带 CSRF 的管理会话可修改 API 根地址、密钥、
  模型名、视觉能力和系统提示词；普通 Bearer 客户端不得修改。Windows 本机后端仅在固定回环地址和
  `QINGJUAN_TRUST_LOCAL_ADMIN=1` 同时成立时接受 Flutter 设置页写入。密钥不写入客户端偏好、不从后端回显，所有客户端都不直连供应商。
- `/api/v1/translation-model/check?force=false` 只读取当前配置的进程内缓存状态，Bearer Token 调用不得发起任何出站请求。
  Linux 只有带 CSRF 的管理会话可调用 `force=true`；Windows 本机模式可由受信回环客户端在保存后调用。接口返回 `enabled`、`configured`、`available`、
  稳定状态、模型名、视觉能力、检查时间、延迟和脱敏说明；不得返回 API 根地址、密钥、请求头、供应商响应原文或完整异常。
- 启用且配置完整时，管理员自检向规范化后的 `/v1/chat/completions` 发送固定、无用户正文的最小探针，最多请求 8 个输出
  Token，用于验证地址、密钥和模型确实可调用。相同配置的结果在单进程内缓存 60 秒；保存新配置后只有管理员显式检测才会发起新探针。
- 模型密钥与规范化 Origin（scheme、host、port）绑定。Origin 变化时，`apiKeyAction=keep` 必须清除旧密钥，管理员必须为新地址
  重新录入密钥；仅路径变化可沿用同 Origin 密钥。`mangaOcr` 的外部 OCR 地址和密钥遵守同一规则。
- 模型和外部 OCR 所有请求共用一个出站安全边界：默认只允许 HTTPS，解析全部 A/AAAA 后拒绝回环、私网、链路本地、保留、
  多播和云元数据地址，并将 TCP 连接固定到已校验 IP，禁止环境代理和自动重定向。局域网自建模型必须由 Linux 运维方在
  `QINGJUAN_MODEL_ENDPOINT_ALLOWLIST` 中配置精确 Origin，例如 `http://192.168.1.20:11434`；该白名单不得通过业务 API 修改。
  运维方应使用 `sudoedit /etc/qingjuan/backend.env` 添加或修改该值（多个 Origin 用逗号分隔），然后执行
  `sudo systemctl restart qingjuan-backend`；重跑安装脚本时必须保留已配置的白名单。
- 未启用或配置不完整属于可解释状态，接口仍返回 `200`；认证失败、接口不兼容、限流、网络或供应商故障映射为稳定的
  `failed` 状态。服务端日志只记录状态和模型名，不记录密钥、探针内容、API 地址或供应商响应正文。
- `/api/v1/meta` 声明 `translationModelCheck` 能力。Flutter 在元数据握手成功后立即调用自检；模型不可用不阻断书库、
  阅读和下载，但连接状态必须提示翻译不可用。所有翻译执行继续在 Linux 任务执行器读取当前服务端配置，禁止客户端
  配置覆盖或本地回退。

## 3. 数据库与文件

- 所有 SQL 使用参数绑定。
- 需要多步一致性的写操作使用事务。
- Schema 变化必须提供可重复、可回滚或可恢复的迁移策略。
- 删除书籍前解析并校验目标路径，不能删除文库根目录或任意用户路径。
- 文件名必须同时满足服务端文件系统和 Android 分享/下载目标的安全限制，并处理保留名、尾随点和长度限制。
- 数据目录通过 `QINGJUAN_DATA_DIR` 或统一解析函数确定，禁止在业务代码散落绝对路径。
- 数据库、封面、章节、译文和临时文件的所有权必须清楚。
- 数据库存储相对数据根的稳定存储键，不把机器绝对路径作为跨请求、备份或迁移标识。
- SQLite 启用 WAL、外键和有限 `busy_timeout`；当前任务队列与链接任务要求单进程、单 Uvicorn worker。
- 时间字段对外使用 UTC ISO 8601；旧的无时区字段迁移时按明确的服务器本地时区解释。

## 4. 抓取与外部服务

- 网络请求设置连接、读取和总超时；重试必须有上限和退避。
- 验证 URL scheme，只允许业务需要的 `http` / `https`。
- 防止 SSRF：拒绝环回、链路本地、私有网段和不可信重定向，除非某个明确的本地集成经过单独授权。
- 控制并发，避免对第三方站点造成突发压力。
- 解析器按站点或协议拆分，通用清洗与持久化逻辑复用。
- 站点 HTML 变化视为正常故障，错误应指出站点和阶段，不吞异常。
- 翻译和 OCR 请求不得记录原始密钥；正文日志要限制长度。
- 尊重目标站点条款、robots、版权与用户所在地区法律。
- 目录中的 VIP、订阅、付费或其他访问状态只作为元数据保留，不得据此提前过滤章节或拒绝抓取。只要当前解析器能从上游响应中取得并验证可用正文或漫画页面，就默认解析和保存；当前格式尚未实现、上游没有返回可用内容或内容完整性校验失败时，应返回明确的能力或上游错误。不得伪造账号、购买状态或上游响应。
- 番茄小说作品页解析服务端渲染的 `window.__INITIAL_STATE__`，目录以 `chapterListWithVolume` 为准。`isChapterLock`、`needPay` 等字段作为访问状态提示保留在目录中。导入请求通过 `downloadMode` 明确选择 `all`（全部下载）或 `on_demand`（先写目录清单）；旧客户端未传该字段时保持 `all`，移动端导入界面对番茄小说默认推荐 `on_demand`。章节下载参照 `D:\Code\bookweb\fanqie\app\clients\reader.py` 直接请求官方 `/reader/{itemId}` SSR 页面，不启动外部 FastAPI 服务；请求携带同源 Referer，并对传输错误、可重试状态码、空响应和缺失 `__INITIAL_STATE__` 的临时风控页统一执行有上限的退避重试。随后交叉校验正文字符数与章节声明字数；正文为空或仅有试读片段时返回可执行错误，完整正文则记录内容来源、访问方式和校验结果。账号 Cookie 仍只用于账号状态和书架同步，不参与章节请求。
- Linux 后端完成 `on_demand` 或其他仅写目录清单的导入后，必须立即由服务器从最早未缓存章节开始按目录顺序尝试缓存完整目录中的全部章节，而不是等待客户端打开阅读器；单章上游未返回可解析内容时记录失败并继续。缓存任务归 FastAPI 应用生命周期持有，不绑定发起导入或读取章节的 HTTP 请求；客户端断开或退出不取消任务，服务重启后根据章节清单与已落盘文件继续未完成部分。Windows 本机后端保留“读取当前章并预取后续章节”的轻量策略。

### 站点解析插件

- `python-backend/app/site_plugins/` 是内置解析器清单的唯一权威来源。每个站点模块声明稳定 ID、显示名称、
  域名匹配、作品类型、能力、默认启用状态以及预览、章节和搜索处理器；同一实现服务多个域名时仍按用户可理解的
  站点拆成独立模块。通用网页回退必须排在所有明确站点之后。
- `/api/v1/plugins` 返回公开模块元数据、当前后端的启停状态和账号型插件的非敏感连接状态，`PUT /api/v1/plugins/{id}`
  只更新 `enabled`。账号型能力使用统一的 `/api/v1/plugins/{id}/account/...` 与
  `/api/v1/plugins/{id}/bookshelf/import-jobs` 协议；不支持相应能力的插件返回 `404`。所有接口不得返回 Cookie、上游登录令牌、
  账号 ID、内部请求头或解析器私有状态，登录与导入响应使用 `Cache-Control: no-store`。
- 声明 `account_login` 的模块可提供 `/api/v1/plugins/{id}/account/login-qrcode` 登录流程和只含 `loggedIn`、`expiresAt` 的账号状态；
  声明 `bookshelf_import` 的模块可提供异步书架导入任务。二维码流程 ID 必须是后端生成的不透明 ID，第三方 `sessionKey`、Cookie、
  CSRF 值和账号标识不得出现在普通响应、SQLite、日志或异常中；退出登录和后端停止时清理内存会话。
- 公开元数据中的类别、版本、域名、作品类型、标签和能力必须由各模块声明并与实际处理器一致，以便 Windows 本机客户端与
  Linux 管理界面据此完成分组、搜索、只读详情和标准账号操作。`account_login`、`cookie_login`、`bookshelf_import`
  只能在后端确实注册对应处理器时声明。当前没有任意插件参数 Schema、依赖管理或安装接口，任何界面不得据此推断插件市场、
  热加载能力或允许提交插件代码。
- 插件状态保存在当前后端 SQLite。新增模块以代码声明的 `defaultEnabled` 初始化，升级不得覆盖用户已保存的选择；
  删除或重命名稳定 ID 必须提供显式迁移。
- 禁用必须由后端执行，而不是只隐藏客户端入口。作品预览、导入、按需章节下载、后台预取和内置站点搜索在发出
  第三方请求前都要检查对应插件；已缓存的本地章节仍可阅读。错误必须指出被禁用的插件及“插件配置”恢复路径。
- 外部 Legado 书源规则与内置站点插件是两个资源：前者保留导入、兼容性和独立启停，后者随程序发布且不可编辑代码或删除。
  Windows 本机模式可在 Flutter“插件配置”中启停；Linux 远程模式只在服务端 `/admin/#plugins` 管理，Flutter 自动隐藏入口。
  两类资源的 API、模型和持久化不得混用。
- 若以后允许标准账号协议以外的插件专属参数，后端必须提供带类型、默认值、必填约束、说明和校验错误的结构化配置 Schema，
  并负责原子保存与版本迁移；不得要求 Flutter 为每个站点维护专用表单分支。
- 扫码登录和书架导入属于能力驱动的运行操作，不属于插件参数 Schema。客户端按能力渲染统一动作，不以插件 ID 推断按钮；
  后端负责拒绝未知、已禁用或未声明相应能力的模块。

### 本地文档导入

- 小说格式支持 `TXT` / `TEXT`、Word `DOCX` 与 `EPUB`；旧版二进制 `.doc` 必须先转换为 `DOCX`。
- 漫画格式支持 `PDF`，导入时逐页渲染为本地 PNG，并作为单个漫画章节保存。
- 格式识别以后缀和内部结构校验为准，客户端选择的作品类型不能绕过后端校验。
- DOCX / EPUB 作为 ZIP 容器处理时必须限制条目数、解压后总大小并拒绝目录穿越路径。
- 大文件先按块写入 `DATA_DIR/import-cache/`，解析和 PDF 渲染在线程池执行；无论成功失败都要清理临时文件。
- 当前大小限制为文本 64 MB、DOCX / EPUB 256 MB、PDF 1 GB，PDF 最多 5000 页。

### 章节导出

- 已下载的小说章节支持导出为 `TXT`、`TEXT`、`DOCX` 或 `EPUB`，产物必须通过本地导入器的结构校验。
- 漫画章节支持导出为多页 `PDF`，也支持打包为 ZIP；ZIP 内按章节分目录，并按清单顺序使用 `001`、`002`……命名并保留原图片扩展名。
- 详情页顶部的“下载全部/下载所选”与单章下载按钮使用相同的格式选择流程；多章小说合并为一个文档，多章漫画 PDF 按章节与页面顺序合并，图片模式先创建作品目录再按章节分目录。
- 有有效译文或译图时优先导出翻译内容，否则回退到原始内容；不得混用已失效的译图缓存。
- 导出接口只在 `DATA_DIR/exports/` 生成受控产物并返回产物元数据与认证下载 URL，不接受客户端文件路径。
- 产物使用不可猜测 ID、固定有效期和定时清理；客户端流式下载完成后再写入 Android 用户授权的位置。

### 漫画图片翻译

- 处理顺序固定为文字检测与 OCR、分区翻译、原文清除、译文排版，不允许跳过 OCR 直接让生成模型改整张图。
- Linux 后端默认运行 RapidOCR，得到文字和坐标后再将纯文本交给 OpenAI 兼容模型翻译；翻译模型不得被假定支持图片输入。RapidOCR 使用部署时安装的 ONNX 小型模型，必须延迟初始化并复用单例，不得在服务启动或识别期间静默下载模型。RapidOCR 结果为空、失败或平均置信度不足时返回明确诊断，不能依赖 Windows OCR 补偿生产能力。
- 只有用户明确开启“使用模型辅助识图”时才能向模型发送漫画图片。视觉模型用于补充竖排字、小字、描边字和拟声词；视觉候选必须先通过原图像素证据校验，未被本地 OCR 覆盖的候选还要经过第二次视觉识别确认。合并时按文字一致性与区域重叠裁决，冲突区域优先采用本地 OCR 文本。
- `bbox` 只表示紧致文字区域，`body_bbox` 表示气泡或旁白框，`safe_box` 表示可排版的安全内区，三者不得混用。本地 OCR 只有紧框时，必须根据原图中的连通背景色恢复容器边界；同一容器里的分列文字合并为一个翻译区，不能把推断出的容器再次裁回文字紧框，也不能把整页背景误作气泡。
- 根据原图文字像素估算前景色、描边色、字号与粗细倾向；无法从像素可靠恢复字体名称时，使用 Linux 后端已安装且支持目标语言的近似字体。
- 原文清除只能操作文字蒙版的膨胀区域：纯色气泡使用背景色回填，复杂纹理从蒙版边缘向内进行局部邻域修复，禁止使用整块模糊、重绘整个气泡或改变原图尺寸。
- 译文优先保留原文横排或竖排方向，以原字号为起点逐级缩小；长竖排译文应利用气泡宽度自动分成从右到左的多列，不能缩成浪费容器宽度的单条细列。超出气泡容量时先请求模型在保留完整语义的前提下精简措辞，仍无法容纳时将完整字形图层等比缩放到气泡安全蒙版内。不得截断、跳过或让文字越过原气泡，并记录溢出、压缩比例、清除方式和平均原字号诊断。

## 5. 后台任务

任务至少包含：

- 稳定 ID、类型、资源 ID；
- `queued`、`running`、`completed`、`failed` 等状态；
- 总数、完成数、进度与用户可读消息；
- 创建、更新时间；
- 脱敏错误和分级日志。

任务执行器必须：

- 限制并发；
- 在资源被删除后安全停止；
- 重启后将未完成任务恢复为可解释状态；
- 失败时保留可重试信息；
- 不因单个任务异常终止整个工作进程。

漫画翻译每完成一页就原子更新断点元数据。任务页通过结构化的逐页结果接口读取 OCR 原文与译文，
并按结果序号增量获取；正文不得复制到任务日志或错误字段，正在运行的任务也不得等整章结束后才
展示已完成页面的文字。

## 6. 客户端后端生命周期

Flutter 客户端启动时：

1. 读取平台允许的连接模式、远程根地址和安全存储中的远程 Token；Android 始终归一化为远程模式；
2. Windows 本机模式固定使用 `http://127.0.0.1:19453`，先校验现有监听者是否为兼容青卷后端，再按需启动随包
   `backend/qingjuan-desktop.exe`；开发态才允许从仓库 `python-backend` 使用系统 Python 启动；
   端口已有健康响应但元数据返回 401 时，说明有启用远程 Token 的青卷服务占用本机端口，必须给出结束占用服务或切换远程模式的
   可执行提示；客户端不得复用远程 Token、覆盖该服务或按端口终止未知进程；
3. 远程模式未配置地址或 Token 时标记为 `unconfigured`，选择设置区并显示连接引导；
4. 远程模式保存前校验地址与 Token，失败时保留输入且不得回退本机；
5. 调用元数据接口校验服务标识、API 版本与能力；服务声明模型自检能力时随后执行模型自检；
6. 后端连接成功但模型不可用时保留 `ready` 并附带翻译告警，随后加载首屏数据；
7. 连接、认证、本机启动或兼容性检查失败时标记为 `failed`，保留客户端 UI、设置输入和重试入口；
8. 切换模式或服务器成功后停止旧轮询与心跳，离开本机模式时终止客户端自己启动的进程，清空旧页面状态后再加载。

携带远程 Bearer Token 的连接成功后启动设备心跳；本机无 Token 模式不登记远程设备。应用退出、连接失败或切换服务器时
必须停止旧心跳。设备登记失败或被封禁时应使用后端可读错误，不得回退本机进程或通过更换随机设备 ID 自动绕过封禁。

只有 Windows 本机生命周期基础设施可以调用 `Process.start`、解析随包后端或在源码树中查找开发后端；Widget、Controller
和 Android 代码不得调用。应用退出时回收自己启动的本机进程并关闭 HTTP 客户端、TTS、Timer 与订阅，绝不终止外部
Linux 服务或占用同一端口但不属于当前客户端的进程。开发者可在确认 PID、命令行和创建时间后手工清理明确的孤立开发进程，
但该操作不属于客户端自动恢复逻辑。

## 7. Android 平台层

- `MainActivity` 只负责承载 Flutter 引擎与系统生命周期，不复制 Dart 业务逻辑。
- Manifest 只声明实际使用的网络等权限；文件选择优先使用系统 Storage Access Framework，不申请广泛存储权限。
- 应用显示名称、包名、版本和图标保持一致，最低支持 Android 8.0（API 26）。
- 公网地址必须由 Dart 校验为 HTTPS；私有网络 HTTP 是显式兼容能力，Android 网络配置不得成为绕过地址校验的入口。
- 原生插件必须说明用途、权限、数据处理和卸载影响。

## 9. Linux 多用户部署

Linux 的权威部署入口位于 `deploy/linux/`，使用原生 Python 虚拟环境与 systemd，不提供 Docker、
Compose 或随仓库分发的反向代理配置：

- `/opt/qingjuan/app` 只作为 root 管理的 Git 控制仓库；活动服务通过 `/opt/qingjuan/current` 指向
  `/opt/qingjuan/releases/<commit>/{app,venv}`。首次安装可由 `releases/legacy` 指向原始仓库与虚拟环境，
  第一次成功更新后即切换为不可由服务用户写入的独立 release。
- systemd 仅运行一个 Uvicorn 进程；禁止多 worker、多实例或多个服务共享同一 SQLite 数据目录。
- 持久化数据固定在 `/var/lib/qingjuan`，服务配置与只供管理员查看的原始连接 Token 位于
  `/etc/qingjuan`，均不得提交到仓库。
- `QINGJUAN_AUTH_TOKEN_SHA256` 是非回环监听的必需配置，所有 Bearer 校验仍只使用摘要。原始 Token 不进入
  进程环境、命令行或普通服务日志；`QINGJUAN_CONNECTION_TOKEN_FILE` 仅指向受限连接文件，原始值只有
  `sudo qingjuan-info` 和管理员主动触发、带 CSRF 的 `/admin/api/connection-token/reveal` 响应可以读取。
- 管理界面先用只读状态接口取得掩码与摘要指纹，不得在页面初始化时返回原始 Token；显示响应使用
  `Cache-Control: no-store`，页面只在内存中保留并于 60 秒后隐藏。旧部署缺少连接文件权限或文件内容与摘要
  不一致时只报告“不可显示”，不得返回文件路径或摘要以外的诊断细节。
- `QINGJUAN_BROWSER_EXECUTABLE` 指向系统 Chromium；漫画本地识别使用 RapidOCR。
- systemd 日志仍可通过 `journalctl -u qingjuan-backend` 查看；后端同时把 Uvicorn 请求、任务、抓取器和应用异常
  写入 `/var/lib/qingjuan/logs/server.jsonl` 结构化轮转日志。管理界面只读取此文件的最近记录，不执行
  `journalctl`，也不授予服务用户读取其他系统日志的权限。
- 运行日志写入前和 API 返回前都执行敏感字段脱敏；连接 Token、Authorization、管理密码、Cookie、CSRF、
  会话签名密钥和模型供应商密钥不得出现在消息中。轮转上限为单文件 2 MiB、保留 2 个备份。
- 自助注册始终要求唯一邮箱；公开策略由 `GET /api/v1/auth/registration-policy` 返回。管理员可分别启用邮箱验证码和
  固定身份牌，两项同时启用时必须同时通过。邮箱验证码只保存 PBKDF2 摘要，绑定规范化邮箱、10 分钟过期、成功注册后
  一次性消费，并同时执行邮箱与来源 IP 限流。注册验证在高成本哈希前执行来源 IP 限流，验证码与身份牌哈希不得阻塞
  异步事件循环；固定身份牌长度为 8–128 个字符，且只保存带随机盐的密码摘要。
- SMTP 与身份牌由带管理会话及 CSRF 的 `/admin/api/registration-settings` 维护。SMTP 支持 `starttls`（默认）、
  `ssl` 和仅供无认证本地 Relay 使用的明文 `none`，明文连接不得提交认证账号或新密码；密码与身份牌使用
  `keep` / `replace` / `clear` 更新语义，并在同一写事务内合并，避免并发保存把新密钥回滚为旧值。所有管理响应、校验响应和日志均不得
  回显 SMTP 密码、身份牌或验证码。Windows 本机单用户模式下注册策略、验证码与注册设置接口统一返回 404。
- GitHub 登录使用 OAuth App Device Flow，并且只请求无 scope 的公开身份。设备码、访问 Token 与轮询状态只在有界的后端内存流程中短暂保存；
  Token 只可用于固定的 `https://api.github.com/user` 身份复验，随后立即丢弃。数据库只保存不可变的 GitHub 数字用户 ID 和当前登录名，
  ID 建立唯一索引；未绑定身份不得登录或自动注册。绑定、解绑与 2FA 管理都要求当前用户会话，敏感操作还必须再次校验本地密码。
- 可选 2FA 遵循 RFC 6238：HMAC-SHA1、6 位、30 秒、最多前后一个时间步，并原子保存最后一次成功计数器以拒绝重放。每用户密钥随机生成，
  使用独立稳定的 `QINGJUAN_2FA_ENCRYPTION_KEY` 域隔离派生 AES-GCM 密钥加密保存，不随管理密码或管理会话密钥轮换。恢复码至少 128 位熵、
  只返回一次、以该独立根密钥的另一域 HMAC 保存且原子一次性消费；登录 challenge 有效期、
  单流程尝试次数和跨 challenge 的用户 / 来源限流都必须有界。Windows 本机模式不得挂载 GitHub 或 2FA 账号接口。
- `sudo qingjuan-info` 从管理员连接文件读取原始 Token，并可在后续需要时再次打印；安装脚本将配置目录设为
  `0750 root:qingjuan`、连接文件设为 `0640 root:qingjuan`，服务配置文件仍保持 `0600 root:root`。
  这是供 Windows / Android 客户端配置和管理界面按需显示使用的持久化入口。
- 安装和 `sudo qingjuan-info` 同时输出 `${QINGJUAN_PUBLIC_URL}/admin/` 管理地址；初始随机管理密码仅由安装脚本
  成功完成时输出一次。遗失密码时运行 `sudo qingjuan-password` 交互改密，或运行
  `sudo qingjuan-password --generate` 生成新的随机密码；两种方式均重启服务并注销现有管理会话。
- 直连 HTTP 仅允许在可信局域网、Tailscale/WireGuard 等私有网络中使用。公网访问仍必须在服务前配置
  运维方选择的 HTTPS 反向代理，FastAPI 不直接终止公网 TLS。

首次部署先在服务器拉取仓库，再运行安装脚本：

```bash
sudo mkdir -p /opt/qingjuan
sudo git clone https://github.com/Tavre/QingJuan.git /opt/qingjuan/app
cd /opt/qingjuan/app
sudo bash deploy/linux/install.sh
sudo qingjuan-info
```

安装脚本优先检测 Tailscale IPv4，再从服务器网卡选择私有 IPv4，自动生成 FastAPI 根地址并监听
`0.0.0.0`。不会联网查询或自动暴露公网 IP；检测不到私有地址时，必须先配置私有网络，或使用
`--url https://域名` 指定已配置 HTTPS 反向代理的地址。`--url` 不包含 `/api/v1`；只允许 SSH 隧道访问时
使用 `--url http://127.0.0.1:19453 --bind 127.0.0.1`。
安装脚本生成 32 字节随机 Token 和独立随机管理密码、写入服务端摘要、创建虚拟环境、安装 systemd 单实例服务与
独立的 root 在线升级服务，并将客户端连接信息、管理地址和首次管理密码打印到控制台。后续既可在管理界面的
“后端升级”中检查并安装固定上游版本，也可使用：

```bash
sudo bash /opt/qingjuan/app/deploy/linux/update.sh
sudo qingjuan-info
```

在线升级 API 只负责同步、原子写入固定且无命令参数的 `/run/qingjuan/update-request.json`，不得直接以 FastAPI 子进程执行
`update.sh`，也不得接受 URL、分支、路径或 shell 参数。`qingjuan-updater.path` 触发独立 root oneshot；升级状态以
脱敏 JSON 原子写入 `/var/lib/qingjuan/backend-update.json`，因此 FastAPI 重启后仍可查询。root 升级器只从当前分支配置的
固定 upstream fetch 到专用 ref，并要求请求 candidate 与该 ref 完全一致；随后用 `git archive` 在独立 release 中完成
全新 venv、静态资源、权限和 Python 导入预检。最终短暂停服并备份 SQLite，通过 `current` 符号链接原子切换，连续验证
新 PID、版本和 commit；失败时恢复旧 current、控制仓库、全部 unit/管理命令、配置和数据库快照。回滚材料位于
`0700 root:root` 的 `/var/lib/qingjuan-updater`，只有旧服务通过健康检查后才清理；回滚异常必须保留并报告
`ROLLBACK_FAILED`。安装、更新、改密和卸载共用维护锁。

不含在线升级器的旧部署使用旧版脚本拉取本版本后，可能需要再执行一次新版 `update.sh` 才能安装 path unit 和运行器；
管理 API 在完成引导前必须返回 `unsupported` 和明确的终端操作提示。

卸载程序时默认保留 `/var/lib/qingjuan` 以及含独立 2FA 密钥的受限 `/etc/qingjuan`：

```bash
sudo qingjuan-uninstall
```

需要同时永久删除书库数据和密钥配置时，直接执行 `qingjuan-uninstall --purge-data`。卸载脚本只允许删除固定的青卷目录，
并在保留数据时保留 `qingjuan` 系统用户，避免书库文件失去属主。

备份必须同时覆盖 SQLite、书籍文件与 `/etc/qingjuan/backend.env` 中的独立 2FA 密钥；数据库与密钥缺一不可。默认做法是停止
`qingjuan-backend`，配套备份整个 `/var/lib/qingjuan` 和受限配置文件后再启动；恢复到临时目录验证数据库与清单后才能替换生产目录。当前不承诺无停机
备份、集群或对象存储。恢复后必须同时校验用户、会话摘要、书架所有权与文件目录的一致性。

## 10. 安全检查

- [ ] 无认证后端只监听 `127.0.0.1`；远程后端配置 Token 且由私有网络或 HTTPS 保护。
- [ ] `/healthz`、公开 DTO 和错误响应不泄露服务器路径或敏感配置。
- [ ] Token 只发送到青卷同源地址，设置接口不回传密钥明文。
- [ ] 管理密码只保存慢哈希；管理 Cookie 为 HttpOnly/SameSite，写请求校验 CSRF，改密后旧会话失效。
- [ ] API 密钥、Cookie、正文和本机路径未进入日志。
- [ ] 文件删除、导出和导入路径经过边界校验。
- [ ] URL 与重定向经过 SSRF 检查。
- [ ] Android 客户端不包含或启动 Python；Windows 只在用户明确选择本机模式时启动随包后端。
- [ ] Windows 本机后端只监听固定回环地址，远程失败不回退，退出或切换时只回收客户端拥有的进程。
- [ ] Windows ZIP 与 APK/AAB 不包含数据库、测试数据、服务 Token、签名材料或开发密钥。
- [ ] 依赖许可证与 GPL-3.0 分发要求已复核。
- [ ] Linux 以 systemd 单进程单 worker 运行，数据目录、备份恢复和 Chromium/RapidOCR 能力已验证。

### 番茄章节解析

- `python-backend/app/fanqie_parser.py` 负责网页 `__INITIAL_STATE__`、目录锁定状态、正文 HTML 和自绘字体反混淆；未知字体映射保留原字符。`scraper.py` 内嵌 `D:\Code\bookweb\fanqie` 的公开阅读页请求约定，对 HTTP 200 空页或缺失 SSR 状态的临时失败也执行同一组有限重试。
- 网页只返回试读、限制提示或不可用内容时，由 `python-backend/app/fanqie_app.py` 调用番茄阅读 APP 的全文接口；`fanqie_crypto.py` 实现请求签名、密钥注册响应解密和正文 AES-CBC 解密。密钥只保存在单次后端进程的内存中。
- 抓取顺序为网页完整正文优先，网页返回试读片段或限制提示时回退 APP 全文接口；两条路径都失败时章节保留为未下载并记录错误，不写入错误占位正文。
- `on_demand` 导入只保存元数据、封面和完整章节目录，不能让导入请求等待正文抓取。Windows 本机后端在阅读时同步缓存当前章并有限预取后续 20 章；Linux 后端在目录写入后由应用级任务持续缓存全书，但任意所选章节及其下一章必须立即越过顺序队列并行准备。预取失败只记录诊断，不覆盖当前正文；删除书籍或关闭后端时必须回收相关任务。
- `all` 导入保持逐章下载全部正文的离线流程。界面必须提示长篇作品可能耗时较久，且用户选择不能被章节数量自动覆盖。
- 设备参数可通过 `QINGJUAN_FANQIE_DEVICE_ID` 和 `QINGJUAN_FANQIE_INSTALL_ID` 覆盖；默认值仅用于匿名接口请求，不记录账号 Cookie。
- 固定样本验证命令：`Set-Location python-backend; python -m pytest tests/test_fanqie_parser.py tests/test_fanqie_app.py`。
