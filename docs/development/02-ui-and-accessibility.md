# UI、交互与可访问性

## 1. UI 技术基线

Windows 使用 Flutter `fluent_ui`；Android 使用统一主题的 Flutter 原生 / Material、flutter_miuix 与移动兼容组件。移动端以[2026重构规范](../design/mobile-redesign.md)为准，本文旧移动布局示例不再作为设计约束。Microsoft
[`microsoft/fluentui`](https://github.com/microsoft/fluentui) 是视觉与交互参考；
其 React/Web 包不适用于 Flutter，不得为了名称一致混入 WebView 或第二套前端框架。

Windows 与 Android 共享业务能力和 Controller，但维护两套明确的平台呈现，不再仅凭窗口宽度互换顶层 UI：

- Windows 以 v1.3.4 桌面端为视觉基线：使用青绿色 Fluent 强调色、Segoe UI Variable 字体、Windows 自绘标题栏、
  可折叠且可拖拽调宽的 `NavigationView` / `NavigationPane`，以及 8 px、无装饰阴影的 WinUI 内容表面。缩窄窗口只能
  折叠或压缩 Windows 侧栏并重排内容，不得切换为 Android 悬浮底栏、移动端大标题或触控卡片壳层。
- Android 使用 v1.4 起形成的触控优先移动端风格，包括移动端标题、底部导航、系统安全区和阅读器沉浸交互；手机横屏与
  平板只在该移动视觉内调整列数和内容宽度，
  不切换为 Windows 工作区侧栏。
- 平台判断与宽度断点职责分开：平台决定视觉系统和顶层导航，宽度只决定当前平台内部的换行、列数和侧栏展开状态。

Linux 管理界面是独立的运维入口，使用 React、TypeScript 与 Ant Design。它不得引入 Flutter/WebView，
也不得把 Ant Design 控件带入 Flutter 客户端。管理界面使用紧凑桌面布局，并在窄屏保持登录、导航、表格和表单可操作。

### 1.1 Linux 管理界面视觉系统

管理界面直接遵循 Ant Design 6 的企业级后台信息层级，不沿用 Flutter 客户端的纸张色、陶土色、Mica 或大幅营销式视觉：

- 首次打开默认使用浅色主题，以纯白容器、`#f5f5f5` 页面底色、低对比细边框和 Ant Design 蓝色主操作构成层级；
  不使用装饰渐变、拟物印章或厚重投影。
- 提供显式的浅色 / 深色切换，深色主题使用 Ant Design 暗色算法并保持相同的信息层级。主题选择只作为当前浏览器的
  设备偏好保存，不上传服务端，也不得与管理密码、Token、Cookie 或 API 密钥存放在一起。
- 桌面端使用常驻侧栏、64 px 顶栏和分层内容区；浅色主题使用白色侧栏与浅灰内容区，深色主题使用 Ant Design
  暗色算法对应的表面色并保持相同层级。在线状态、实例 ID、刷新、主题与退出操作必须在同一顶栏内稳定对齐，
  不能因为窄宽度换行后挤占页面标题。
- 页面标题、筛选工具、统计卡片、表格和表单沿用 Ant Design 默认密度与 8 px 圆角；卡片主要靠背景和边框分层，阴影只用于
  浮层或必要的悬浮反馈。
- 登录页保持单一中心任务：品牌、简短说明、密码输入和登录按钮。不得使用占据半屏的宣传文案或与管理行为无关的装饰面板。
- `assets/logo.png` 是全项目唯一品牌图标源文件。Flutter 关于页、README、管理界面、Windows `.ico` 与 Android 各密度启动器图标都必须由它复用或生成；不得继续把旧 `qj_icon2.png` 或历史 `app_icon.ico` 内容当作源图。生成后的 `assets/app_icon.ico` 只作为 Windows 资源入口。平台生成资源保持透明圆角、安全边距和原始纵横比，不得拉伸或裁掉卷轴。
- 管理界面的启动与登录状态复用仓库根目录的 `assets/logo.png`；登录后的侧栏只显示产品名称与“服务管理”说明，避免重复图标占用导航宽度。登录前后统一使用同一套系统字体回退，不另外绘制文字印章或使用页面专属字体。
- 360 px 宽度下侧栏改为抽屉式导航，顶栏隐藏次要实例文字，表格保留横向滚动；主题切换在登录页与登录后始终可达。
- 左侧导航提供“设备管理”；概览只统计最近 120 秒内在线的客户端。设备页按在线、离线、已封禁显示名称、平台、对端地址、
  首次连接和最后活动时间，并提供带明确确认文案的封禁 / 解封操作；不得只用颜色表达设备状态。
- 左侧导航提供“系统诊断”；首屏先显示运行时长、请求量、服务端错误和剩余磁盘，再展示数据库、任务执行器、
  数据目录与运行日志检查。健康、注意和异常状态必须同时使用图标、文字与语义色；最近异常只显示已脱敏摘要。
  “下载脱敏报告”输出适合提交 Issue 的 JSON，不得包含 API 密钥、密码、Cookie、绝对路径或服务器文件内容。
- 管理界面的模型设置卡提供“模型自检”，保存启用的模型配置后立即执行一次强制自检，并显示模型名、可用状态、
  延迟和脱敏错误。Flutter 设置页不再重复编辑 API 地址、密钥、模型名、视觉能力或系统提示词，只显示 Linux
  服务端模型的只读自检状态和重新检测入口；服务端不可用时不得暗示客户端存在本地翻译回退。
- Linux 管理界面左侧导航提供“插件管理”，展示当前服务随版本发布的站点解析器，并允许管理员搜索、按启停状态筛选和修改
  开关。页面必须说明修改对连接该 Linux 后端的全部客户端生效，且不提供安装、卸载或上传代码入口。

规则：

- 优先使用 `NavigationView`、`Button`、`TextBox`、`InfoBar`、`ContentDialog` 等 Fluent 控件。
- 两个以上功能重复的组合模式提取为项目共享 Widget。
- 不修改第三方包源码；差异通过薄封装、Theme 或组合解决。
- 禁止 Material 与 Fluent 控件混搭形成两套视觉。依赖内部使用 Material 图标字体不等于允许使用 Material 页面组件。
- 图标优先使用 Fluent 图标集，不用 emoji 充当功能图标。
- 外观模式的三项图标必须与语义一致：“跟随系统”使用系统 / 设备图标，“浅色”使用亮度 / 太阳图标，“深色”使用月亮图标；
  不得在 Windows 上用手机图标表示系统主题。说明文字按当前平台写 Windows 或 Android，选中状态同时使用边框、文字和语义。

### 1.2 插件管理交互

插件管理可借鉴 Koishi 官方控制台的[插件清单、启停、分组与详情配置](https://koishi.chat/zh-CN/manual/usage/market)，
但只采用与青卷现有后端能力一致的信息架构：

- 页面先提供搜索和“全部 / 已启用 / 已停用”状态筛选，再按小说、漫画、通用回退等后端声明的类别分组；分组是内容分类，
  不是可拖拽编辑的用户配置。
- 每个插件必须同时显示名称、明确启停状态和简短职责。详情展示稳定 ID、版本、匹配域名、作品类型、能力与标签；无域名的
  通用回退必须说明其回退角色，不能伪装成某个具体站点。
- Windows 选择本机后端时，Flutter 使用符合 v1.3.4 Fluent 桌面基线的“分组清单 + 详情”双栏工作区，并保持键盘焦点、
  hover 与紧凑控件密度；切换至 Linux 远程后端后，桌面侧栏和设置页不得继续显示 Flutter“插件配置”入口。
- Linux 远程后端的插件由 `/admin/#plugins` 中的 Ant Design 管理页维护。Android 始终使用 Linux 远程后端，因此客户端不显示
  插件配置入口；管理员在服务器管理界面修改后，所有连接该后端的客户端共享结果。
- Windows 插件工作区使用页面专属的宽内容上限，充分利用大窗口；双栏只在可用宽度至少 960 px 时启用，分组清单宽度保持
  320～400 px，详情栏至少保留约 624 px。清单与详情分别拥有独立的 Fluent 滚动条和滚动位置，内容末端为滚动条预留安全边距；
  滑块默认收起、滚动或 hover 时出现，不得常驻压住启停状态、标签或详情文字。
- 启停是当前版本唯一可编辑项。保存期间锁定对应开关，服务端确认后才更新状态；筛选后无结果时区分“没有插件”和“没有匹配结果”。
- 当前解析器随后端发布，不提供插件市场、安装、卸载、在线更新、任意代码加载、嵌套自定义分组或虚构的热重载状态。
  将来增加插件专属配置时，字段、默认值和校验必须由后端结构化元数据声明，客户端不得按插件 ID 硬编码表单。

## 2. 移动端产品化视觉原则

设计关键词：沉浸、纯净、轻盈、直接、专注阅读。手机端参考夸克小说等成熟阅读产品的通用信息组织和
单手交互密度，但不得复制其商标、品牌色、专属插画、活动入口或具有识别度的页面组合。

- 主色使用青卷自有的清澈蓝色，配合纯白表面、冷浅灰页面底色与高对比正文；强调色只用于主操作、阅读进度和状态锚点。
- 书架首屏应有明确的继续阅读区域；工具页使用紧凑标题，避免装饰性头图、营销标语和重复品牌展示。
- 非阅读器页面不使用渐变、玻璃模糊、背景插画或大面积装饰图形；层级主要由留白、明度和极轻分隔线建立。
- 卡片使用 14～18 dp 圆角；封面、主操作和选中导航获得更强视觉权重，普通列表保持平面和连续。
- 普通内容使用冷浅灰背景与纯白表面；深色主题使用深灰底和略亮表面，保持同一信息层级而不是简单反色。
- 表单和长文本区域减少装饰，输入、错误和保存状态仍以清晰可读为第一优先级。
- 动画以 140～240 ms 的淡入、位移和选中态变化为主，尊重系统“减少动态效果”设置。
- 禁止霓虹描边、低对比玻璃、无意义噪点和妨碍文字阅读的大图背景。

### 2.1 阅读产品信息架构参考

青卷可研究[夸克官方小说介绍](https://www.quark.cn/article009)、
[番茄小说公开产品页](https://apps.apple.com/cn/app/id1468454200)与
[起点读书官方产品页](https://www.yuewen.com/app/?type=appqd)中稳定的阅读产品模式，但只吸收通用交互规律：

- 书架是阅读状态面板，不是后台数据表。首屏依次呈现问候与快捷操作、最近阅读、书架筛选和封面墙。
- 最近阅读只突出一本书，必须同时显示封面、上次章节、进度和“继续阅读”主操作；没有书时退化为明确的导入引导。
- 手机书架默认使用三列封面墙，书名与进度在封面下方，不把每本书做成占满整行的设置卡。
- 搜索把输入框放在首要位置，常用书源和搜索状态紧随其后；搜索结果保持封面、书名、作者或来源、简介的固定视觉顺序。搜索列表中的简介可以限定行数以维持列表密度；书籍详情中的简介不得截断，手机端在固定高度的独立区域内上下滑动查看完整内容，Windows 详情直接展示完整简介。
- 插件配置、书源管理、任务和设置属于不同工具页面，使用紧凑标题、状态概览和分组列表；不得复用书架的营销式头图。
- 底部导航贴近系统导航区并保持稳定，未选中项只显示中性图标和标签；选中项通过品牌色、字重和小面积背景共同表达，不使用五个同等醒目的大胶囊。
- 页面背景使用冷浅灰或深灰，内容表面接近纯白或深色抬升面；一屏只保留一个高权重蓝色主操作。
- 不引入推荐流、广告、签到、会员、社区和短剧等青卷没有的业务，也不复制参考产品的图标、文案、商标或专属布局。
- Android 移动端导航固定为“书架、搜索、书源、任务、我的”；“我的”首先呈现 Linux 用户登录状态，再承载设备偏好、服务器连接和关于入口，
  不新增商业画像、推荐或会员入口。Windows 本机后端隐藏注册、登录和退出操作，仅显示隐式本机管理员状态。
- 本节只改变 Android 呈现层；Windows 的 Fluent/Mica 主题、桌面侧栏、键鼠密度、页面结构和交互不得随移动端重构而改变。

### 2.2 移动端页面视觉系统

除阅读器外的手机页面必须共享同一套页面层级，不能让书架、搜索、任务和设置分别形成互不相干的卡片风格：

- 页面背景使用一层稳定冷浅灰底色，标题区、内容区和底部导航通过间距与明度区分，不为每个区块增加描边。
- 一级标题保持 28～32 dp 的明确场景感；副标题只说明当前状态或下一步，不重复页面名称。标题区最多保留一个高权重主操作和一个图标操作。
- 内容首页（书架、搜索）允许使用一张浅蓝平面面板承载继续阅读、输入或当前状态；工具页（插件配置、书源管理、任务、设置）使用紧凑概览和圆角分组列表，不使用营销式大头图。
- 同类设置项放入同一圆角分组，分组内部用缩进和低对比分隔线组织；不得让每个字段都成为带阴影的大卡片。
- 手机端文本输入关闭拖动选区时的放大镜，但保留系统原生的选区、复制、粘贴和上下文菜单；连接 Token 等密码输入框遵循同一规则，不能通过关闭交互选区来规避放大镜。考虑到部分 Android 键盘或系统在密码框中不提供可靠的长按菜单，Token 输入框还必须在字段旁提供带文字语义的“粘贴”按钮，读取纯文本剪贴板后只写入当前控制器，不记录、回显或上传剪贴板内容。
- 统计值、连接状态和任务状态使用小面积状态胶囊或语义色圆点。成功、警告和错误必须同时有文字或图标，不得只依赖颜色。
- 书籍与搜索结果始终优先展示封面、书名和阅读信息；操作按钮退居条目末端，不与内容争夺首屏视觉焦点。
- 空状态使用紧凑插图式图标、原因和唯一主要下一步，垂直位置接近首屏中部，不在标题下制造整屏不可操作空白。
- 底部导航采用 12 dp 左右边距的悬浮圆角卡片并控制在 76～84 dp，使用高透明度表面、细描边、受控局部模糊和轻阴影表达液态玻璃；不得使用渐变、噪点、厚重阴影或五个大胶囊。选中项使用小面积浅蓝背景、蓝色图标和字重变化；切换时图标允许 0.92～1.06 的短缩放，但不得让五个入口整体位移。
- Android 状态区与系统导航区使用透明系统栏，由页面底色延伸至安全区；不得在内容页顶部保留与主题割裂的黑色或纯色横条。
- Android 从一级页面进入的详情、阅读等独立路由必须自行处理状态栏与底部手势区安全距离，不能依赖外层 `AppShell` 的 `SafeArea`。阅读器路由存续期间保持 Flutter 画面 `edgeToEdge` 铺满整个窗口，再由 Android 窗口只隐藏顶部状态栏、保留底部系统导航/手势区；不得切换到会让窗口重新避让状态栏的手动覆盖层模式。原生层必须把状态栏颜色、Decor 背景和刘海短边布局同步为当前阅读配色，并在窗口重新获焦、应用恢复前台和阅读配色变化后重应用隐藏状态，避免 ColorOS、MIUI 等系统重置 Insets 后露出窗口黑底。页面退出、进入听书等非阅读路由时恢复透明 `edgeToEdge` 和顶部状态栏，且不得使用同时吞掉底部手势区的 `immersiveSticky`。
- 小说正文统一使用两字首行缩进和两端对齐。客户端先清理上游段首空白，再由文本布局插入随系统文字缩放同步变化的两字布局占位；不得把全角空格、兼容字符或其他不可见正文字符当作缩进交给两端对齐引擎。连续模式和 Windows 阅读器把每个正文项居中限制到阅读栏宽度时，正文项必须强制占满统一阅读栏，不能只给 `maxWidth` 后让短段按固有宽度收缩并被分别居中。无论设备字体、段落长度或换行结果如何，所有段落首个正文字符都必须落在同一全局横坐标，自动换行和跨页续行则从正文左边界开始。分页、上下滚动与 Windows 阅读器必须共享这一排版规则，漫画图片及图片下方翻译不套用小说缩进。

页面专项规则：

- 书架：首页突出最近阅读，封面墙负责浏览；搜索框属于藏书区，不与“添加书籍”争夺主操作。
- 搜索：输入区、搜索引擎选择与当前可用状态组成一个整体；搜索引擎明确提供“书源”“夸克”“番茄”“起点”和“笔趣阁”五项，默认保持现有“书源”行为，
  切换后不得继续展示上一引擎的结果或错误。紧凑宽度下选择器与输入框允许分行，但搜索按钮仍是该区域唯一高权重操作。
  有结果后收起说明性空状态，结果条目按固定信息顺序连续排列，并明确显示实际结果来源。
- 插件管理：Windows 本机模式只显示随本机后端发布的内置站点解析器、能力说明与启停开关；Linux 远程模式把相同职责放在
  服务端管理界面。保存中开关替换为局部进度，失败时恢复服务端原状态。
- 书源管理：只管理内置搜索源、手动导入和 Legado 兼容规则，保留 v1.4 的导入、运行状态与列表层级；不得在本页混入站点解析插件。
  紧凑宽度下操作按钮换行或等分，不能挤压书源名称、状态和标签。
- 任务：运行中任务优先，历史任务按状态分组；进度、类型、更新时间和失败原因形成清晰的纵向阅读顺序。
- 设置：主题、听书、服务器和翻译分别成组；组标题留在卡片外，组内控件使用设置行，保存状态常驻但不遮挡内容。
  Windows 本机后端就绪时，翻译组直接显示模型、密钥、提示词和 OCR 配置以及独立保存按钮，不显示管理地址或浏览器跳转入口。
- 详情与关于：使用明确返回层级。详情页以封面、书名和主要阅读操作为首屏，章节与管理操作后置；移动端标题必须完整位于系统状态栏安全区之下；关于页先展示产品身份，再展示链接、平台和许可。

非阅读器页面的状态切换、导航选中、卡片按压和内容出现使用 120～240 ms 的可中断动画；页面不得为了播放动画延迟请求、保存或导航。系统请求减少动态效果时使用零时长。

动效与渲染性能遵循以下基线：

- 页面级切换统一复用共享动效组件：Windows 使用克制的淡入与短距离水平位移，Android 使用同方向的轻量淡入位移；前进与返回方向必须连贯，不能让各 Feature 自行定义互相冲突的曲线。
- 按压、hover、选中态使用主题中的短时长 token；内容切换与路由使用中等时长 token。业务请求、持久化、滚动输入和导航状态先执行，动画只负责呈现结果且必须可被下一次交互打断。
- 系统请求减少动态效果时，页面切换、路由、阅读器控制层与选择反馈全部使用零时长；不得只关闭部分动画后仍保留缩放或大幅位移。
- 长列表不做逐项入场或持续阴影动画。优先动画化 `transform` 与 `opacity`，避免在每一帧改变大面积布局、模糊半径或阴影；复杂且静止的动画子树应隔离重绘。
- `BackdropFilter` 只用于导航栏、阅读浮层等范围明确的液态玻璃表面，并必须由圆角裁剪与重绘边界限制采样区域；如果组件背后只有固定纯色或设备关闭透明效果，则退化为更高不透明度表面，避免没有视觉收益的持续背景采样。
- 以 profile / release 模式检查滚动和页面切换；60 Hz 设备的单帧 build 与 raster 总预算为 16.7 ms，出现连续慢帧时先缩小重绘和模糊范围，不能用延长动画掩盖卡顿。
- Android 阅读器的正文滑动期间不得持续采样整块背景模糊，也不得在每个呈现帧遍历章节标题并查询全局坐标；章节定位允许按短间隔合并检查，停止滑动后必须补做最后一次检查。
- Android 长列表只缓存临近视口的必要内容：正文、章节和封面列表不得以超大 `cacheExtent` 提前布局多屏复杂文本或图片。翻页进度保存需要合并连续手势产生的请求，退出、切章时仍立即保存最终位置。
- Android 横向翻页的自定义效果只能改变已隔离页面的合成属性；不得在手势每帧重新计算大面积阴影。Windows 阅读器和桌面列表沿用既有交互与缓存策略。
- Android 在同分辨率存在高刷新率显示模式时，由原生 Activity 优先请求不高于 120 Hz 的最高模式；如果设备只提供更高档位，则选择最接近 120 Hz 的模式。省电模式、温控和厂商策略仍可降低最终刷新率，应用不得通过修改系统设置强制覆盖用户选择。
- 120 Hz 动效的 UI 与 Raster 线程各自以 8.33 ms 为单帧上限，并在 Profile / Release 构建中检查 P90、P99 与最大值。只有 `dumpsys display` 确认应用实际运行于 120 Hz 时才能宣称真机 120 Hz；60 Hz 模拟器只能作为帧耗时代理，不能作为高刷验收结果。

默认空间系统使用 4 的倍数：

- 紧密：4、8；
- 控件内部：12；
- 相关区块：16；
- 页面区块：24、32。

正文不小于 14 dp 等效逻辑像素；辅助文字不小于 12 dp。优先使用平台系统字体与完整中日韩回退。

## 3. 响应式布局

Android 布局必须覆盖手机竖屏、手机横屏和常见平板宽度：

- 手机使用底部导航承载书架、搜索、书源管理、任务和设置五个主要入口；“关于青卷”作为设置区的独立次级页面。Android
  不显示插件配置入口，也不把插件开关塞回书源管理页面；插件由所连接 Linux 后端的管理界面维护。
- 手机端不设置独立的固定品牌顶栏，页面内容直接从当前场景的标题区开始；底部导航使用悬浮圆角液态玻璃卡片、小面积选中胶囊和轻阴影，但不得遮挡内容或削弱图标、文字对比度。
- Android 平板继续使用移动端顶层导航和触控视觉；宽度增加只用于内容分栏和最大宽度，不得切换为 Windows 工作区侧栏。
- 页面内容设置合理最大宽度，平板横屏不把文本无限拉长。
- 网格按可用宽度调整列数；最小卡片宽度不得导致按钮或标题截断。
- 页面从 `MediaQuery.paddingOf` 获取系统栏和手势区域，底部操作不得被导航手势遮挡。
- 对话框在手机上接近全宽但保留 16 dp 外边距，主要按钮无需横向滚动。
- Windows 使用 v1.3.4 风格的 `NavigationView`、自绘窗口标题栏与左侧 `NavigationPane`。“书源管理”始终是独立入口；
  “插件配置”仅在本机后端模式显示，切换 Linux 远程模式后立即隐藏。宽屏展开侧栏并允许拖拽调宽，窄窗口使用 Fluent
  紧凑侧栏，但始终保留 Windows 桌面页面标题、控件密度和键鼠焦点。
- Windows 的文件选择、滚轮、键盘导航与窗口缩放必须可用，主要流程不得依赖触控手势。
- 平板顶层框架可以显示轻量品牌标识，但不能挤占主要内容；手机端不得在页面标题区之外重复品牌或页面名称。返回按钮只在关于、详情、阅读器等存在上级页面的场景出现，并响应系统返回手势。
- 格式选择等两行选项必须让标题和说明使用同一左边界，不得出现标题居中、说明左对齐的混合排版。
- 触控目标至少 44 × 44 dp，主要操作之间保留足够间距；不得依赖 hover、右键或拖动缩放才能完成操作。

不得使用设备型号硬编码断点。平台视觉边界依据 Flutter 目标平台；进入对应视觉后，响应式判断再依据可用逻辑宽度、
文字缩放与系统安全区。不为 Android 引入 Material 页面组件，也不得让 Windows 因窗口变窄而套用 Android 页面壳层。

## 4. 状态与反馈

每个异步区域必须显式覆盖：

- 初次加载：显示进度和正在执行的动作；
- 空状态：说明原因并给出一个主要下一步；
- 成功状态：内容稳定呈现，不反复闪烁；
- 局部更新：保留现有内容并显示轻量进度；
- 失败状态：用户可理解的原因、重试按钮和必要上下文；
- 禁用状态：防止重复提交，同时保持文字可读。

通知规则：

- 可恢复的小错误使用页面内 `InfoBar`。
- 破坏性操作使用确认对话框，按钮明确写“删除书籍”等动作，不只写“确定”。
- 后台任务开始后立即反馈任务已创建，并提供查看入口。
- 日志和底层异常不得直接当作主界面文案。

## 5. 表单与文案

- Label 常驻，不用 placeholder 代替字段名称。
- 必填、格式、范围在提交前后均有一致校验。
- 错误紧邻对应字段；跨字段错误放在表单顶部。
- 保存成功不清空用户仍可能复用的配置。
- 文案使用简体中文、动词开头、避免模糊术语。
- API 密钥默认遮挡，不在日志、错误或截图提示中回显。
- 管理界面的“后端 API 密钥”特指客户端连接 Token：默认只显示掩码和指纹，必须由用户主动点击后才请求原文，
  60 秒后自动隐藏；复制按钮必须有明确语义。翻译与 OCR 供应商密钥仍只允许替换或清除，不回显原文。
- “运行日志”使用独立导航页展示时间、级别、来源和完整消息，支持搜索、级别筛选、手动刷新与可关闭的自动刷新；
  错误堆栈允许换行和复制，但不得出现连接 Token、管理密码、Cookie、CSRF 或模型供应商密钥。

## 6. 触控、键盘与焦点

- 主要流程必须能仅通过触控完成；平板外接键盘时 `Tab` / `Shift+Tab` 顺序与视觉阅读顺序一致。
- 文本输入设置合适的键盘类型、提交动作与自动填充提示；Token 不启用普通文本自动保存。
- `Enter` 只在语义明确时触发主要操作；多行文本中不得误提交。
- Android 系统返回键/手势优先关闭对话框和详情层级，再决定是否退出应用。
- 对话框打开后焦点进入有效控件，关闭后返回触发元素。
- 焦点指示必须清晰，不通过移除 outline 隐藏。
- 长列表应保持原生滚动和惯性，不劫持系统级手势。

### 6.1 沉浸式阅读器

- 阅读器正文是唯一常驻层。Android 阅读器打开后始终隐藏顶部时间状态栏，只保留底部导航/手势区；轻触正文中部仅显隐应用内顶栏和底部工具栏，退出阅读器必须恢复宿主页系统界面。正文使用 `MediaQuery.viewPadding` 保留物理安全区，不能因控制层显隐改变排版，也不能为已隐藏工具栏保留固定空白。
- 视觉采用青卷自有的“纸张 + 浮层”层级：正文、顶栏和底栏使用同一配色体系；操作层使用可读性足够的半透明毛玻璃、细描边和柔和阴影悬浮在正文上方，不占用正文布局，不使用桌面窗口式卡片、大描边按钮或居中设置弹窗。
- 顶栏只显示返回、作品名、当前章节和轻量更多入口。普通底栏第一行使用“上一章 / 章节进度 / 下一章”，第二行提供目录、听书、日夜切换和设置，不放书架级导航。
- 阅读设置从底部原位展开，按“字号、纸张配色、阅读方式、翻页动效、排版与按键”分组，并允许在窄屏和横屏中独立滚动。字号使用减小/数值/增大操作；背景至少提供白色、纸张、护眼、淡蓝和夜间五种高对比度配色；翻页提供覆盖、平移、淡入、无动画和上下滚动。
- 阅读设置同时提供行距、原文/译文和“音量键滑动 / 翻页”开关。配色、字号、行距、翻页方式和按键偏好立即生效并持久化。
- 章节目录使用从底部进入的高占比章节面板，保留作品名、章节总数、当前位置和连续滚动列表；手机端不显示桌面式 `ContentDialog`。
- 毛玻璃控制台的圆角、边距、分组顺序、图标组合和动效曲线均采用青卷自有参数；只借鉴通用阅读交互，不复制参考应用的标志性位置、文案、品牌色或运营入口。
- 顶栏、底栏、设置面板和目录使用 180–320ms 的淡入、位移或缩放动画；按钮按压和选中状态有轻量反馈。系统请求减少动态效果时必须切换为零时长或最弱动画。
- 左右分页模式支持左右滑动；上下滚动模式保持原生惯性滚动。启用“音量键滑动 / 翻页”后，音量加对应上一页或向上移动约一屏，音量减对应下一页或向下移动约一屏。
- 音量键只在阅读器存活且用户明确开启时拦截；设置关闭、页面退出或应用失去阅读器上下文后，音量键必须恢复系统调节音量行为。
- 目录使用可滚动章节列表，当前章节有文字和颜色双重选中状态；选择章节后关闭目录并直接定位，不要求逐章跳转。
- 分页模式到达章节边界时可继续滑动或使用音量键切章；滚动模式在当前章末尾直接连接下一章标题和正文，不插入整页加载状态。音量键在滚动列表首尾触发相邻章节补载时，同一次按键仍须完成向上或向下移动，不能要求再次按键。
- 漫画在分页模式中一页对应一张图片，在滚动模式中保持连续长图；翻译文本紧随对应图片，图片加载失败只影响当前页。

## 7. 可访问性

- 文本与背景常规对比度至少 4.5:1，大文本至少 3:1。
- 不只用颜色表达成功、失败、选中或任务状态。
- 图标按钮必须有 Tooltip 和语义标签。
- 图片提供有意义的语义；纯装饰图片从语义树排除。
- 动画尊重系统减少动态效果设置，时长短且支持被打断。
- 字体放大后允许换行和滚动，不遮挡操作。
- 加载进度、错误和结果数量应可被辅助技术感知。
