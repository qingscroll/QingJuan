# 书籍空间与文件发布配额

## 1. 统计与清理边界

书籍空间页按实际受控文件统计原文、译文、图片、其他书籍数据和导出临时文件。数值为逻辑文件字节数，不是磁盘分配块大小，也不包含共享 SQLite、全服插件包和其他账号书籍。软链接、Windows junction、特殊文件和越界路径会中止统计或清理；不跟随链接读取数据。

阅读时的章节缓存就是正文或原图，不是可以无损清除的第二份副本。因此当前唯一开放的清理类别为 `exports`：`DATA_DIR/exports/<bookId>/<32 位小写十六进制 ID>.<txt|text|docx|epub|pdf|zip>` 下的直接文件。未知文件、嵌套目录、原文、译文、图片、清单、恢复日志、笔记、阅读进度和作品信息一律保留。全局导入缓存与图片工作流临时目录缺少可靠的书籍归属，不提供按书籍删除入口。

用户先获取预览，查看文件数量、格式、大小、时间和文件标识，再明确确认。清理使旧导出链接失效，之后可以从原书重新导出。预览只读，不会删除文件。

## 2. 请求、确认与维护边界

相对 `/api/v1` 的接口：

| 方法与路径 | 请求 / 响应 |
| --- | --- |
| `GET /books/{id}/storage` | `BookStorageReport`，类别、实际总量、保留量、可清理量 |
| `POST /books/{id}/storage/cleanup-preview` | 固定 `categories: ["exports"]`，返回 `StorageCleanupPreview` |
| `POST /books/{id}/storage/cleanup` | `cleanupId, confirmationToken`，返回实际删除数量/字节及更新后的统计 |

全部接口要求当前用户拥有该书，其他账号统一返回 `404`。返回值不公开磁盘路径。预览有效期十分钟，服务器最多保存 256 份；预览表用线程锁保护。确认令牌 HMAC 绑定账号、书籍、预览 ID、过期时间、文件路径及大小/修改时间/inode/device 清单。文件清单在预览后变化、预览过期、令牌错误会返回 `409`，要求重新预览。一个预览至多消费一次。

清理 POST 独立放入管理路由集合，以避免请求本身计入普通业务维护门后形成自等待；它仍是普通用户的书籍操作，并不因此获得管理权限。先在 `gate.operation(wait=False)` 中认证、登记设备并检查书籍归属，退出操作后再进入 `quiesce_storage`。后者只持有全局 `gate.exclusive`：拒绝新业务并等待完整文件流和已有任务写入排空，默认等待三十秒，繁忙则 `409`；不重启工作线程。拿到独占后才检查预览和最新书籍归属、运行任务状态，逐个删除允许清理的文件。与备份恢复使用同一维护门，因此不可交叉交换/删除文件。

如果请求被取消，线程中的文件操作仍可能继续，服务会等待该线程真正结束才释放维护门。删除时发生占用或文件变化则停止后续操作，返回已经释放的真实字节和剩余文件提示，不扩大清理范围。

## 3. 公共计量与原子发布

`storage_meter.measure_owner_storage(owner_id, connection=None)` 汇总此账号登记的书籍目录、其导出目录和持久化临时导入目录。重复或嵌套目录去重。公开用量包含实际暂存文件；配额发布检查使用 `published_only=True`，排除内部暂存与恢复文件，避免一份待发布内容被计算两次。

`storage_quota.quota_write_bytes(path, bytes)`、`quota_write_text(path, text)` 和 `quota_replace(temporary, target)` 在 `DATA_DIR/library`、`DATA_DIR/exports` 下验证目录归属、真实文件大小与增加量，串行完成额度检查和 `os.replace`。超额返回 `413`，原有目标文件保持原字节。限额降低后，允许原文件缩小或等长替换；不自动删除已下载结果。导出产物也占账号空间。

锁顺序为 `BEGIN IMMEDIATE` 后进程 `PUBLISH_LOCK`，在同一连接直接读取 `resource_limits.storage_bytes`，禁止检查过程中再打开写连接。`connection=` 与 `owner_id=` 可供已有事务复用；传入外层连接时，调用方必须负责外层提交失败后的文件回滚。小说译文校对使用已有恢复日志，并持有发布锁直到提交或回滚完成，恢复旧文件不能被新的更小限额拒绝。

若新文件已经发布、数据库提交失败，文件发布器会尝试恢复旧内容。恢复操作再次因 I/O 错误失败时，必须保留含旧字节的 `.quota-<id>.old` 副本，不能在 `finally` 中删除最后的恢复副本；返回明确的 `503`，说明旧文件尚未恢复、恢复副本已保留并需要管理员检查存储。此时目标可能仍是新内容，不能声称旧文件已经恢复。原来不存在目标文件时，若回滚删除新文件也失败，同样返回 `503` 并明确新文件尚未移除。两种失败均释放发布锁，保留实际文件状态供检查，不自动重试覆盖；恢复副本不属于普通用户可清理的导出文件。

`.quota-*`、`.quality-*`、`.manifest-*`、`.chapter-*.tmp`、`*.part`、`.translation-quality-<index>.json` 及 `.manga-translation-<hex>.tmp` 子树是内部未发布内容。写入这些暂存仍检查归属；最终发布到正式目标时才检查增加量。它们不是清理 UI 可删除的内容。逻辑额度不能代替主机剩余磁盘监控，执行中的临时数据和恢复副本仍需要可用磁盘空间。

不在上述受控书库/导出目录的写入保留原调用方的路径验证和原子写语义，支持图片工作流系统临时目录以及独立测试。此兼容行为没有创建任意路径 HTTP 写入接口，也不能作为外部输入路径安全校验使用。部署保持一个后端进程使用数据目录；进程锁不提供多个独立后端共同写库的保证。

## 4. 新书导入与中断遗留

首次写入前使用 `with provisional_book_storage(owner_id, root): ...` 登记 `storage_provisional_roots(storage_key, owner_id, created_at)`，同一上下文中完成 `save_book`。root 必须是受控书库下的相对存储键，不能是整个书库，也不能与另一账号目录重叠。导入写入继承账号上下文。

退出上下文后，目录为空或所有剩余文件都位于同账号已登记的书籍路径内时，注销临时登记。支持在线导入 root 下的语言/书名子目录；其余残留文件继续保留登记并计入账号实际空间。导入失败、清理失败或进程中断不得丢失计量登记；冷启动不擅自删除残留书籍文件。

整机备份保留登记及文件，显式本机迁移将登记归属映射给目标账号；恢复检查安全相对键与跨账号目录重叠。

## 5. 客户端与验证

DTO 为 `lib/core/models/storage.dart`，入口 `showBookStorage(context, bookId:, mobile:)`。Fluent 与 Material 使用相同控制器。只有用户明确确认才发清理请求，后端/账号切换立即清空文件预览和统计、撤销弹框确认，迟到结果不会写入新账号状态。确认失败必须重新预览，不自动重发删除请求。

## 6. 用户额度与公平任务调度

管理界面“用户 → 资源限制”显示账号实际文件占用、当天模型请求次数与额度。管理员通过带会话及 CSRF 的 `GET/PUT /admin/api/users/{ownerId}/resources` 查看/修改策略，写入必须包含 `expectedRevision`，并发修改返回 `409`；普通用户通过 `GET /api/v1/resources/usage` 读取自己的用量。`null` 表示不限额，`0` 表示不允许增加对应资源。

存储额度以受控书籍及导出文件的逻辑字节数计算，不包含共享数据库和插件；不预先删除已存在的内容。降低额度后，既有文件仍可阅读，缩小文件或清理导出仍可执行。每个模型 POST 在真实网络请求之前原子计数，超时、失败、重试和手动强制自检均计入调用账号当天的用量；无用户上下文的内部健康探针单独处理。日界按 UTC 零点重置，响应同时返回具体重置时间。

下载／翻译任务队列按账号轮转，同账号内部保持 FIFO；晚进入队列的账号有下一轮执行机会。该调度发生在任务之间，不抢占已开始的长章节或任务，不对链接导入另做并发预算。备份保留用量表和额度策略；显式迁移保留目标服务自己的账号策略。
