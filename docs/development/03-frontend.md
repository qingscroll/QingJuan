# Flutter 客户端开发规范

## 1. Dart 基本规则

- 遵循 `flutter_lints`，不得无理由忽略 analyzer 警告。
- 提交前执行 `dart format`，不手工对齐空格。
- 默认使用 `final`；确实需要重新赋值时才使用 `var`。
- 公共 API 声明明确类型；避免 `dynamic`，解析 JSON 时逐字段校验。
- 异步函数返回具体 `Future<T>`，不丢弃 Future；刻意后台执行时使用 `unawaited`。
- 空安全是领域约束的一部分，不通过大量 `!` 绕过。
- 构造函数尽可能 `const`。

## 2. Widget 边界

页面负责布局与把用户事件交给 Controller，不直接实现网络或复杂业务。建议结构：

```dart
class LibraryPage extends StatefulWidget {
  const LibraryPage({super.key});
}

class _LibraryPageState extends State<LibraryPage> {
  @override
  Widget build(BuildContext context) {
    final controller = AppScope.of(context).libraryController;
    return PageFrame(
      title: '书架',
      child: _LibraryContent(controller: controller),
    );
  }
}
```

拆分标准：

- 可独立命名、复用或测试的视觉区块提取为 Widget。
- 对话框放在独立文件或清晰的私有 Widget 中。
- 大列表条目使用独立 Widget，避免在 `itemBuilder` 中堆积复杂树。
- 设置等工具页同时包含主题、设备能力、后端连接和服务状态等三个以上独立区域时，页面只负责 Section 组合、
  保存入口和跨 Controller 编排；各区域的布局与短生命周期 UI 状态放入 `widgets/` 下的领域化 Widget，
  不得把连接切换、数据重载等跨功能流程复制到 Section 内。
- 只为缩短文件而抽取无语义的一行 Widget 没有价值。
- 搜索结果中的书籍简介属于有界摘要，可以设置 `maxLines` 和 `TextOverflow.ellipsis`。书籍详情必须保留完整简介：手机端使用带独立 `ScrollController` 的固定高度纵向滚动区，Windows 不截断正文；滚动区 Controller 必须随 Widget 释放。
- 所有手机端 `TextBox` 通过共享响应式规则使用 `TextMagnifierConfiguration.disabled`，只关闭放大镜；`enableInteractiveSelection` 和默认上下文菜单保持启用，使长按仍可选择、复制和粘贴。Windows 继续使用 Fluent 默认文本交互。

Widget 不应：

- 创建 `http.Client` 或 `Process`；
- 读写 `SharedPreferences`；
- 解析后端 JSON；
- 持有全局单例；
- 在 `build` 中发起请求或改变状态。

## 3. Controller 与状态

Controller 表达一个功能域的用例和可观察状态：

- 通过构造函数注入 `ApiClient` 等依赖。
- 状态变化后统一通知监听者。
- 暴露只读集合，不让页面任意修改内部列表。
- 防止重复加载、并发保存和销毁后的通知。
- 将后端错误归一化为用户可理解的状态。
- `dispose` 中停止 Timer、订阅和其他资源。

全局 `AppState` 只保存真正跨功能的内容，例如主题、当前导航位置和后端地址。
书架、任务、插件与书源规则、设置分别由自己的 Controller 管理；不得把所有状态塞入一个全局类。

## 4. API 与模型

`ApiClient` 负责：

- 基础 URL、超时和请求头；
- `/api/v1` 路径、Bearer Token 与服务端版本握手；
- JSON 编解码；
- HTTP 状态码到 `ApiException` 的映射；
- 健康检查和资源 API。

领域 Model 负责：

- 从已验证的 JSON 创建类型安全对象；
- 提供不可变字段和必要的值转换；
- 不依赖 Flutter Widget 或 `BuildContext`。

规则：

- URL 使用 `Uri` 组合，不用字符串拼接。
- 每个请求设置有限超时。
- Token 只附加到与已配置后端同源的 URL；第三方封面、跳转或外部下载绝不能携带 Token。
- 非 2xx 读取后端 `detail`，但不能泄露响应中的敏感字段。
- 文件路径和 Android 文档 URI 通过平台适配层处理，不手工拼接斜杠或假设共享文件系统。
- API 字段变化必须同步更新后端模型、客户端模型和契约测试。
- Linux 自助注册在显示表单时读取 `/auth/registration-policy`：邮箱始终必填，邮箱验证码与身份牌按服务端开关动态显示，
  两项同时启用时客户端必须同时提交。策略读取失败时禁止提交并提供重试；每次重新进入注册页刷新策略，避免沿用管理员已修改的旧条件。
- 验证码、身份牌和密码只存在于当前表单内存，切回登录、注册成功或切换后端时立即清空；验证码发送采用可取消倒计时，
  不写入偏好、安全存储、日志或错误正文。Windows 本机模式不得请求或展示注册策略。
- GitHub 登录只面向已经注册并主动绑定的账号。客户端采用 Device Flow 时只显示设备码并打开固定的
  `https://github.com/login/device`，按服务端给出的间隔轮询；不得接受任意验证域名，也不得持久化设备流程、GitHub Token 或
  2FA challenge。未绑定的 GitHub 身份不得自动创建青卷账号。
- 密码或 GitHub 第一因素通过后，如果服务端返回 2FA challenge，客户端进入独立的验证器代码 / 恢复码步骤，完整验证前不得写入用户会话。
  账号安全界面允许当前用户绑定或解绑 GitHub、启用或关闭 TOTP、重新生成恢复码；TOTP 密钥与恢复码只在当前流程中显示，离开、切换后端或
  完成后立即清空。恢复码必须明确提示只显示一次。

搜索页的“书源 / 夸克 / 番茄 / 起点 / 笔趣阁 / 导入插件”引擎选择属于页面临时状态，不写入 `AppState` 或客户端偏好。`SourcesController` 继续统一承载搜索中的
加载、结果和错误状态：书源引擎调用 `/api/v1/sources/search`，夸克、番茄、起点与笔趣阁引擎分别通过稳定内置源 ID 调用
`/api/v1/builtin-sites/search`，再补齐来源名称、语言与导入所需字段并映射为同一个 `SourceSearchResult`。切换引擎必须清空旧结果，
避免界面标签与实际结果来源不一致；加入书架仍复用现有 URL 导入链路。
“导入插件”调用 `/api/v1/plugins/search`，按后端已安装、已启用且声明搜索能力的插件聚合结果，来源 ID 留空以便按 URL 匹配解析器。
插件安装使用内存中的同一份文件字节完成预检和上传；切换后端后废弃旧预检及迟到响应，安装更新不得自动重试。

## 5. 依赖注入与应用启动

`QingJuanApp` 是组合根，按顺序：

1. 初始化 Flutter；
2. 读取持久化偏好；
3. 创建 API 客户端；
4. 检查是否已配置远程后端；已配置时执行认证、版本握手与 Linux 服务端翻译模型自检，未配置时进入设置页；
5. 创建各 Feature Controller；
6. 加载首屏必要数据；
7. 渲染 `FluentApp`。

依赖通过 `AppScope` 或明确构造参数下发。禁止 Service Locator、隐藏全局变量和在 Feature 内重复创建基础设施对象。

## 6. 导航

- 顶层导航由 Shell 统一管理，但平台风格不得只按宽度互换。Windows 的 `DesktopShell` 使用参考微软商店的 Fluent
  `NavigationView` / `NavigationPane`、自绘标题栏、默认带文字的窄侧栏与桌面控件密度；宽屏支持手动展开与调宽，Android 始终使用 v1.4 起形成的移动端
  底部导航与触控页面层级；宽度只控制各自平台内的重排。
- Windows 本机后端模式的左侧导航分别提供“书源管理”和“插件配置”；切换 Linux 远程后端时从侧栏移除“插件配置”，若当前
  页面正是插件配置则回到设置。Android 底部导航只保留“书源管理”，设置区不提供插件入口；远程插件由 Linux 管理界面维护。
  书源与插件不得合并，导入 Legado 规则的操作也不得出现在任何插件管理页。
- 书籍详情和阅读器属于内容层级，不复制一套侧栏。
- 导航目标使用类型或稳定索引，不散落字符串。
- 页面离开时保存必要阅读进度并释放资源。
- Feature 页面不得各自实现顶层导航；平台决定导航风格，逻辑宽度只决定同一平台风格中的展开、折叠、列数和换行。
- 返回按钮由当前路由层级决定，不在顶层 AppBar 放置始终可见的全局返回按钮。

### 6.1 插件配置状态

- `SourcesController` 只保存后端插件清单、逐项保存状态和后端错误；搜索词、状态筛选与当前选中插件属于页面临时状态，
  离开页面后无需持久化。
- 当前选中项使用插件稳定 ID，而不是保存会随启停请求被替换的模型实例。后端刷新、筛选或切换后端后，选中项不存在时退回
  当前可见的第一项。
- 插件分组、搜索和详情完全使用 `/api/v1/plugins` 返回的类别、域名、作品类型、标签、能力、版本与启停状态；不得维护第二份
  站点名称或能力映射。仅面向用户的类别与能力中文标签可由共享展示函数转换。
- 通用插件配置仍只允许修改 `enabled`，因此客户端不得显示可编辑但无法保存的插件参数、依赖、安装版本或运行日志。
  插件只有在公开能力包含 `account_login` / `bookshelf_import` 时才显示后端提供的标准扫码登录和书架导入操作；额外包含
  `cookie_login` 时可显示 Cookie 登录兜底。Cookie 输入使用密码控件，提交后立即清空，不进入页面模型、错误文本或剪贴板
  辅助流程。二维码、本地登录流程 ID、轮询和导入进度只保存在当前页面或对话框状态，不写入客户端偏好。登录成功后刷新插件
  清单中的非敏感账号状态，导入完成后刷新书架。
- Windows 双栏的插件清单与详情各自持有并释放 `ScrollController`，禁用全局自动滚动条后再显式绑定 Fluent 滚动条，避免同一
  `Scrollable` 出现重复滑块。选择另一插件时详情滚动位置回到顶部，清单滚动位置保持不变。
- `AppState` 以“Windows 且当前为本机后端”作为 Flutter 插件入口的唯一可见条件。切换远程模式时同步规范化当前导航状态，
  Shell、快捷键和设置页不得各自维护一套不同判断。Linux 管理页直接复用 `/api/v1/plugins`，不复制插件状态到浏览器存储。

## 7. 持久化

- 轻量客户端偏好可存 `SharedPreferences`：主题、Windows 后端模式、远程后端地址、最后导航位置。
- 连接 Token 使用 Windows / Android 平台安全存储，不得写入 `SharedPreferences`、日志、异常或截图友好的普通文本配置。
  应用不得自动复制、回显或记录 Token；用户在密码输入框内主动调用系统复制、粘贴菜单属于标准文本编辑行为。
- Linux 用户会话 Token 使用独立的安全存储键，只发送到当前青卷后端同源地址。切换服务器、退出登录、账号停用或会话失效时必须清除，
  并同步重置旧账号的书架、任务、搜索结果和轮询状态。
- 书籍、任务、模型凭据、阅读进度和站点插件启停状态由当前后端 SQLite 管理；Windows 本机数据与 Linux 数据互不自动同步。
- 站点插件开关属于当前后端实例，不写入客户端 `SharedPreferences`。多个客户端连接同一后端时读取同一组开关；
  切换后端后必须重新加载，不能把上一后端的状态复制过去。
- 站点账号 Cookie、二维码会话和批量导入中的临时远端书目不写入 `SharedPreferences`；切换或停止后端后视为未登录，用户需要
  在目标后端重新扫码或重新提交 Cookie。已成功导入的青卷书架记录仍按当前后端 SQLite 规则持久化。
- 不在多个位置存同一权威数据。
- 设置保存采用“后端成功后更新本地状态”，失败时保留用户输入并提示。

## 8. 错误与生命周期

- 捕获可预期异常并显示操作建议。
- 不使用空 `catch`；忽略错误时写明原因。
- `mounted` 检查应出现在异步 UI 回调返回后。
- 后端不可用时应用仍应显示诊断和重新连接入口。
- Widget 与 Feature Controller 不得创建、终止或探测 Python 进程。只有 Windows 本机后端生命周期基础设施可启动
  随包可执行文件或开发态源码后端，并必须在切换到远程模式或应用退出时回收自己启动的进程。

## 9. 后端模式与连接生命周期

Windows 支持本机与远程两种显式模式，Android 强制远程：

- Windows 本机模式固定使用 `http://127.0.0.1:19453`，不允许编辑地址或填写 Token。先探测兼容服务，未运行时再
  启动 `backend/qingjuan-desktop.exe`；源码调试可从仓库 `python-backend` 启动同一入口。客户端启动进程时关闭
  `/admin` 管理站点，只允许回环客户端通过业务设置 API 保存模型配置。
- 若 `19453` 已有健康响应但业务元数据返回 401，本机模式必须明确提示“端口被启用 Token 的后端占用”，不能把它描述成
  随包进程启动失败，也不能尝试携带 Linux 远程 Token 或终止不属于当前客户端的进程。
- 本机模式已连接后，设置页直接显示翻译模型、API 密钥、视觉能力、系统提示词和外部 OCR 表单；保存操作写入当前本机后端，
  成功后强制执行一次模型自检。密钥只保留在表单内存和后端 SQLite 中，不写入客户端偏好，也不从后端回显。
- 远程模式使用用户配置的 `https://` 地址，或可信私有网络中的 `http://` 地址，并且必须提供 Token。
- 本机与 Linux 远程连接是两个独立配置档案：模式选择器只决定当前使用哪个档案。本机档案固定保存回环地址和空 Token；
  Linux 档案独立保存地址及安全存储中的 Token。保存、切换或编辑任一档案都不得覆盖、清空或用当前表单值污染另一档案。
  用户在表单中尚未保存的 Linux 地址和 Token，也必须在本次页面内往返切换模式后保留。
- Android 即使读到旧的本机模式偏好也必须迁移为远程；APK 不包含、查找或启动 Python。
- Windows 没有保存过服务器时默认本机模式；V1.4 已保存远程地址的安装继续使用远程模式，避免升级后意外切换数据源。
- 远程连接失败、认证失败或版本不兼容时，只显示对应诊断与重试入口，不得回退到回环地址或本机后端。
- 保存新连接前先调用认证后的元数据接口，校验服务标识、API 版本和能力。
- 元数据声明 `translationModelCheck` 能力时，连接管理器随后调用认证的模型自检接口。自检通过时记录服务端模型名；
  未启用、未配置或供应商不可达时仍允许进入书库和阅读，但连接提示必须明确“翻译不可用”，翻译任务不得回退到
  客户端模型。自检异常不能把供应商密钥、地址或响应原文写入客户端错误。
- Flutter 仅在 Windows 本机模式提供模型供应商配置表单；Linux 远程模式仍由管理界面维护 API 地址、密钥、模型名、
  视觉能力和系统提示词。Android 与 Windows 远程客户端只读取脱敏状态。“重新检测”由当前后端发起，不由客户端直连供应商。
- 切换成功后停止旧轮询和设备心跳；离开本机模式时停止客户端拥有的本机进程；随后清空旧后端页面状态，并重新加载
  书架、插件与书源规则、任务和设置。Windows 单文件后端必须按启动时记录的 PID 回收完整进程树，不得按端口终止未知进程。
  切换模式时保留完整 Linux 远程连接档案，便于用户切回远程服务。
- 多个客户端连接同一 Linux 服务器时只共享服务级书源、插件、模型设置和管理员配置的 Bika 抓取凭据；这些全局配置只有管理员可修改。
  书架、任务、阅读进度以及支持账号书架的插件运行时按登录用户隔离。
  Windows 本机模式不显示用户功能并始终使用隐式本机管理员主体。

认证资源使用与 JSON API 相同的同源请求头。`Image.network`、缓存驱逐和文件下载都必须通过
`ApiClient` 提供的同源判断获取请求头，禁止 Widget 自行读取 Token。

## 10. 远程文件传输

- 导入：系统文件选择器返回用户选择或授权的文件，客户端用 multipart 上传；后端不接收 URI 或本机路径字符串。
- 导出：客户端先请求后端生成产物，响应只包含产物 ID、文件名、大小、类型和下载 URL；客户端再流式下载到用户通过系统选择器授权的位置。
- 漫画图片导出由后端打包为 ZIP，客户端不得假设能访问后端目录。
- 上传与下载必须有进度、有限超时、临时文件和失败清理；下载完成前不得覆盖已有文件，最终落盘使用原子重命名。
- 服务端绝对路径不得进入客户端 Model、成功提示或错误信息。

## 11. 设备听书与朗读风格

听书使用设备系统 TTS，正文不得为朗读上传到未明确配置的云服务。朗读风格通过受限范围内的
语速、音高、标点分句和句间停顿实现；沉浸类风格可以识别对白、问句、感叹句和省略句并逐句调整
韵律。风格预设不能把低质量音色伪装成神经网络声线，设置页必须区分 Natural / Neural 与标准
系统声线，并在未检测到自然声线时给出明确提示。

朗读完成状态通过 TTS 完成、取消和错误事件驱动；不同平台和 TTS 引擎能力不一致时必须降级到可用能力，
不要依赖会把原生结果对象持有到后台回调的
阻塞完成模式。暂停、继续、停止和参数调整的异步异常必须由 Controller 转换为用户可读错误，页面
销毁时只保留一个幂等的 TTS 关闭入口，禁止并发重复停止。

## 12. 阅读器缓存、翻页与章节衔接

- 阅读器以 `作品 ID + 章节索引 + 原文/译文模式` 作为内存缓存键，同一键的并发请求必须合并，不能重复请求后端。
- 当前章节成功显示后立即预取下一章，并在资源允许时预取上一章；缓存至少覆盖当前章和相邻章节，同时设置上限并优先淘汰远离当前位置的内容。
- 显式切章优先同步读取缓存。缓存命中时不得清空正文或显示全屏加载；缓存未命中时保留当前正文，只在控制区显示轻量加载状态。
- 上下滚动模式维护连续章节序列：下一章预取完成后直接追加到列表末尾，接近列表末端时继续预取后续章节；用户从序列顶部继续向上时按需切换到上一章并定位到章末，随后从缓存重新衔接原章节。章节标题经过视口顶部时更新当前章节和进度。
- 左右分页模式只对当前章节做轻量分页；到达首尾边界后从相邻章节缓存切换。文本分页允许按视口、字号和行高估算，但必须保留全部字符顺序。
- 小说正文必须先由同一个段落规范化入口生成：优先使用后端 `paragraphs`，清理每段首尾空白后写入仅供客户端识别的段首标记，并以稳定段间距组合分页文本；只有缺少段落数组时才从 `content` 回退拆分。渲染时把段首标记转换成宽度严格等于 `2 × textScaler.scale(fontSize)` 的布局占位，标记本身不得进入可见正文或交给字体整形。连续模式、分页模式和 Windows 阅读器复用同一富文本构造入口，正文使用 `TextAlign.justify`；连续模式和 Windows 列表中的文字项还必须占满统一的阅读栏约束，不能因短段固有宽度较小而单独居中。短段和自动换行长段的首字必须具有相同的页面全局横坐标，避免设备字体、文字缩放和换行差异改变段首位置。
- 分页与连续阅读的正文边距以 `MediaQuery.viewPadding` 为基准，不能使用随沉浸模式变化的 `padding`，也不能把顶部或底部控制层高度计入正文固定留白。毛玻璃控制层使用 `BackdropFilter` 覆盖在正文之上，显隐时不得触发正文重分页或滚动跳动。
- Android 阅读器进入后先保持 Flutter `SystemUiMode.edgeToEdge`，再通过 `qingjuan/reader` 平台通道同时传递启用状态和当前阅读背景色。原生窗口关闭 decor 避让、允许画面进入刘海短边、只隐藏 `statusBars`，并以阅读背景色覆盖状态栏和 Decor 兜底背景；底部导航/手势区保持显示。窗口重新获得焦点、应用恢复前台和配色变化时都必须重新应用，不能依赖一次性的初始化调用。页面离开或临时进入非阅读路由前由同一通道恢复顶部状态栏、原窗口颜色和刘海策略，再恢复宿主页的透明 `edgeToEdge`。
- 目录跳转会重置当前连续序列或分页索引，并同时预取新的相邻章节；旧缓存可保留到容量淘汰，避免用户往返章节时重复等待。
- Android 音量键通过专用平台通道传递 `up` / `down` 事件。原生层只有在 Flutter 阅读器明确启用后才消费按键，且必须同时消费对应按下和抬起事件。Flutter 层按阅读流分派：分页模式调用上一页/下一页，连续模式平滑移动约 84% 视口；若移动跨越当前连续序列边界，先装入相邻章节、等待布局更新，再用同一次按键完成移动。
- 阅读偏好属于跨书籍客户端偏好，保存在 `AppState` 对应的 `SharedPreferences` 字段；至少包含阅读流、配色预设、字号、行距、分页动画和音量键开关。书籍正文、目录和阅读进度仍以 Linux 后端为权威来源。
- 阅读进度同时保存章节、从零开始的页索引、页数、分页标识与正文字符偏移；界面页码从 1 开始。相同内容和分页标识恢复原页，字号或窗口变化后根据字符偏移定位新页；原文/译文模式随进度保存，旧记录只有滚动比例时继续兼容。连续阅读保存章节内的段落/图片索引及其可见偏移，并根据实际正文视口与文字排版计算章内逻辑页码；Windows 和 Android 连续模式都需展示和持久化页码。页码随排版变化，正文锚点用于恢复位置；不得以懒加载列表的总滚动范围估算页数。
- 同章滚动和翻页均防抖保存，进入后台、返回详情或离开阅读器时提交当前位置。保存队列串行发送并合并中间位置，失败时只重试最新位置；切换账号或后端后丢弃旧上下文的待保存任务。初次正文未加载成功时不得写入默认零进度。返回详情须等待已提交的保存请求结束，再刷新详情和书库页码。
- API 默认只自动重试 GET；创建任务、导入等写请求在响应丢失时不能假定服务端未执行。链接任务使用每次操作独立的 `Idempotency-Key`，同一未确认操作的手动重试复用键，成功后新操作或切换后端生成新键。
- 阅读配色由独立的 `ReaderPalette` 映射为背景、正文、次要文字、控制面板、分隔线和强调色；Widget 不应散落判断全局亮暗主题。夜间配色只影响阅读器，不能强制切换整个应用主题。
- 分页动画是阅读偏好而不是数据模式：覆盖、平移和淡入可共享分页内容与 `PageController`，无动画使用直接跳页；上下滚动仍由 `ReaderFlowMode.continuous` 表达。
- 阅读器操作层使用可中断的隐式动画，且通过 `MediaQuery.disableAnimationsOf` 尊重系统减少动态效果。动画不得阻塞章节缓存读取、进度保存或硬件按键事件。

## 13. 移动端视觉组件边界

移动端页面的视觉规则必须沉淀在共享 Widget，而不是在每个 Feature 中重复颜色和圆角判断：

- `PageFrame` 负责安全区内的页面宽度、标题层级、滚动边距和手机/平板差异。
- `AppSurface` 负责普通、强调、选中三类表面及按压反馈；Feature 只选择语义，不直接复制 `BoxDecoration`。
- 页面主题面板、设置分组、状态胶囊和空状态分别由共享组件表达，颜色统一从 `FluentThemeData` 与项目语义色获取。
- 顶层手机导航由 `AppShell` 使用带稳定 key 的共享页面切换组件切换内容；Windows `NavigationView` 与 `Navigator` 路由使用同一组动效 token。切换动画不得销毁 Controller，也不得改变业务状态。
- Feature 可以为封面、章节和任务等领域内容提供专用条目，但必须复用共享间距、状态和交互动效。
- `lib/shared/motion.dart` 是客户端动效时长、曲线、页面切换和路由动画的统一入口。所有共享动效通过 `MediaQuery.disableAnimationsOf` 决定时长；不得在页面中散落固定长动画或创建无法释放的 Controller。
- 页面与路由动画只包裹呈现层，使用稳定 key 与 `RepaintBoundary` 隔离复杂内容；长列表条目、网络图片解码和 `BackdropFilter` 不参与逐项入场动画。背后只有固定纯色的导航表面不得使用无效背景模糊。
- 手机端对话层统一通过 `lib/shared/mobile_sheet.dart` 的 `showMobileSheet` / `MobileSheet` 使用接近全宽的圆角底部面板，并处理键盘、安全区、关闭语义和减少动态效果；Windows 继续使用 `ContentDialog`。Feature 不得按屏宽把桌面弹窗伪装成手机面板。

页面改造必须至少补充一个手机宽度 Widget 测试；共享组件需要覆盖亮暗主题、长文本或 200% 字体缩放中的一项高风险场景。

## 14. 客户端评审清单

- [ ] 文件和类职责单一，未形成巨型页面或 Controller。
- [ ] Widget 未直接进行 HTTP、进程或持久化操作。
- [ ] JSON 与空值边界有类型保护。
- [ ] Android 不出现本机模式；远程未配置或连接失败不会回退到本机服务。
- [ ] Windows 本机模式只使用固定回环地址，并只回收当前客户端拥有的进程。
- [ ] Token 只从安全存储读取且只发送到青卷同源地址。
- [ ] Android Token 密码框保留原生选区，并提供不会回显或记录内容的显式粘贴按钮。
- [ ] 导入上传、导出下载和认证图片不依赖共享文件系统。
- [ ] 异步状态、重复点击和 dispose 场景正确。
- [ ] 主题、手机/平板布局、触控、系统返回与错误态已验证。
- [ ] 单元和 Widget 测试覆盖新增行为。
- [ ] `dart format`、`flutter analyze`、`flutter test` 全部通过。
